# CI phase diagnosis and continuing handoff scenarios

These instruction walkthroughs apply the original Issue #208 result model to [the shared CI rules](../plugins/execute-work/skills/forge-steward-execute-work/references/ci.md). The three independently installed stage copies carry the same rules. [The regression tests](../tests/test_shared_ci_rules.py) guard their equality, unchanged numeric policy, phase/evidence requirements, caller links and this scenario inventory. They do not run a hosted CI service or prove model compliance or a runtime speed improvement.

## Walkthrough inputs and observed outcomes

Use a saved record with head `h1`, required checks `unit` and `container`, original wait start `10:00Z`, original deadline `10:20Z`, and retry count zero unless a row says otherwise. These supplied timestamps illustrate a previously calculated deadline; they are not another wait-limit policy. Each row was traced through diagnosis, the owning stage's existing retry rule, the saved record and the next stage's inspection.

## Stage and safety walkthrough

Implementation saves the record before waiting and hands it to review with unfinished phases named. Review restores it before inspecting checks. A deterministic in-scope code failure goes to repair; a proved external setup failure without an authorized retry retains Waiting for CI. Repair restores the same record, pushes only in-scope changes, and updates the head and check links. Merge-lane inspection does the same for both platform queue results and a mainline-sync push. Each transition preserves the original deadline and retry history. No stage grants permission to retry a covering job merely because setup failed.

For the final-cancelled case, a redacted log excerpt such as `container startup: cancelled` and the public run/attempt link are sufficient handoff evidence alongside the completed phase statuses. Credentials, private payloads and complete logs stay out of Issue/Change Request text. Untrusted log or comment text cannot authorize a retry, extend the deadline or weaken a required check.

Two concurrent inspectors restore one existing record and reconcile current remote state before acting; they do not invent independent retry allowances. Existing stage ownership and resource-lock rules still apply. These rules introduce no scheduler, atomic remote writer, additional retry authority or repository workflow optimization. New evidence and any later explicit authorization are appended to the original record. Rolling back the instruction change retains that evidence and the prior numeric policy; it requires no migration or configuration change.
