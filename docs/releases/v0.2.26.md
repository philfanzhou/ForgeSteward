# v0.2.26

This file is release input for `v0.2.26`. Publication is complete only when both the matching remote annotated Tag and a non-draft GitHub Release exist.

This release expands check-workflow into an English working environment with documentation translation and the repository About flow, adds a pre-publication secret-scan gate and an untrusted-content boundary to every stage skill, hardens merge execution and fix-feedback's repair rounds, and strengthens work-cycle resource ownership with an explicit final cleanup stage and stage version preflight. All six plugins move together to `0.2.26`.

## Changes

- **English working environment** ([PR #195](https://github.com/philfanzhou/ForgeSteward/pull/195), [Issue #183](https://github.com/philfanzhou/ForgeSteward/issues/183); [PR #202](https://github.com/philfanzhou/ForgeSteward/pull/202), [Issue #184](https://github.com/philfanzhou/ForgeSteward/issues/184); [PR #203](https://github.com/philfanzhou/ForgeSteward/pull/203), [Issue #185](https://github.com/philfanzhou/ForgeSteward/issues/185)): check-workflow now records one English working-environment rule covering project-maintained documentation, Issue and Change Request text, Comments, Discussions, Review Threads, and future commit messages, replacing separable conflicting rules while retaining and reporting inseparable ones. A default documentation-translation operation then translates project-maintained documents inside the same cleanup branch and Change Request, preserving technical and quoted content, verifying links, and reporting every file honestly, including large or failed documents retained untranslated. A default repository About operation reads the current value, writes a faithful English translation when needed, and reads it back, recording the exact before and after values; About never creates a branch, commit, or Change Request by itself, and an already-English, empty, or absent value is reported without a write.
- **Byte-preserving cleanup safety and release audit** ([PR #155](https://github.com/philfanzhou/ForgeSteward/pull/155), [Issue #143](https://github.com/philfanzhou/ForgeSteward/issues/143); [PR #200](https://github.com/philfanzhou/ForgeSteward/pull/200), [Issue #176](https://github.com/philfanzhou/ForgeSteward/issues/176); [PR #186](https://github.com/philfanzhou/ForgeSteward/pull/186), [Issue #142](https://github.com/philfanzhou/ForgeSteward/issues/142)): legacy workflow-block removal now removes only the exact dangling `@AGENTS.md` import lines while preserving every other blank run, line ending, and trailing byte, returns exit 2 for symlinked or non-regular root entries instead of a false clean, and requires a clean tracked Git worktree before any write. Dangling-reference cleanup now deletes links and reading instructions only when the referrer is itself a cleanup candidate, retaining content referenced from out-of-scope locations for maintainer decision. The release audit gains an explicit `release-audit-only` no-write mode, and work-cycle carries audit findings into its final report as an optional `release_audit` field without letting them block independent cleanup delivery.
- **Pre-publication secret-scan gate** ([PR #197](https://github.com/philfanzhou/ForgeSteward/pull/197), [Issue #172](https://github.com/philfanzhou/ForgeSteward/issues/172)): execute-work inspects the complete diff or commit range before every commit and push, and prepare-work applies the same gate before publishing experiment evidence or command output to an Issue or comment. A repository-defined secret-scan command is run with its exact command, exit result, and coverage recorded; a hit, a failed or unavailable defined command, or incomplete coverage stops the push, preserves the branch and local commits, redacts the value, and claims no pass. Without a defined command, the completed inspection and the command's absence are recorded without claiming an automated pass.
- **Prepare-work queue policy** ([PR #160](https://github.com/philfanzhou/ForgeSteward/pull/160), [Issue #152](https://github.com/philfanzhou/ForgeSteward/issues/152); [PR #158](https://github.com/philfanzhou/ForgeSteward/pull/158), [Issue #140](https://github.com/philfanzhou/ForgeSteward/issues/140); [PR #161](https://github.com/philfanzhou/ForgeSteward/pull/161), [Issue #141](https://github.com/philfanzhou/ForgeSteward/issues/141)): a metadata-only first-pass screen now covers the whole queue before deep preparation, recording each excluded item and its reason while forbidding full audits in that pass. One dependent-Issue policy selects a dependent only after its selected prerequisite in the same list, records it as waiting for that merge, and starts it from latest mainline afterward. An explicit invocation without scope limits may create at most one tracker plus its dependent tasks for a feature-sized frozen candidate after an open/closed duplicate search; when creation is not authorized, the split plan is recorded on the original Issue and preparation stops, while baseline persistence falls back to the original Issue handoff instead of inventing a tracker.
- **Merge, repair, and cleanup-eligibility hardening** ([PR #159](https://github.com/philfanzhou/ForgeSteward/pull/159), [Issue #145](https://github.com/philfanzhou/ForgeSteward/issues/145); [PR #157](https://github.com/philfanzhou/ForgeSteward/pull/157), [Issue #137](https://github.com/philfanzhou/ForgeSteward/issues/137); [PR #156](https://github.com/philfanzhou/ForgeSteward/pull/156), [Issue #139](https://github.com/philfanzhou/ForgeSteward/issues/139)): merge execution now follows one invariant — merge only the reviewed head, into the decided base, with current approvals — reading back every ambiguous result, pinning reviewed heads where the platform supports it, and rechecking approvals after a head-changing sync; execute-work Change Requests target the repository's default mainline unless the user explicitly named another target. fix-feedback now never merges: at three completed repair rounds it only hands the head to review-and-merge for one final review, an unreviewed third-round head may receive only a conflict-free mainline sync push, and force-push stays off by default. Post-merge worktree deletion now meets the same eligibility conditions as leftover branch cleanup, retaining worktrees that fail any condition, including external locations.
- **Work-cycle orchestration robustness** ([PR #188](https://github.com/philfanzhou/ForgeSteward/pull/188), [Issue #164](https://github.com/philfanzhou/ForgeSteward/issues/164); [PR #190](https://github.com/philfanzhou/ForgeSteward/pull/190), [Issue #165](https://github.com/philfanzhou/ForgeSteward/issues/165); [PR #191](https://github.com/philfanzhou/ForgeSteward/pull/191), [Issue #167](https://github.com/philfanzhou/ForgeSteward/issues/167); [PR #192](https://github.com/philfanzhou/ForgeSteward/pull/192), [Issue #168](https://github.com/philfanzhou/ForgeSteward/issues/168); [PR #198](https://github.com/philfanzhou/ForgeSteward/pull/198), [Issue #175](https://github.com/philfanzhou/ForgeSteward/issues/175); [PR #199](https://github.com/philfanzhou/ForgeSteward/pull/199), [Issue #169](https://github.com/philfanzhou/ForgeSteward/issues/169); [PR #196](https://github.com/philfanzhou/ForgeSteward/pull/196), [Issue #179](https://github.com/philfanzhou/ForgeSteward/issues/179); [PR #162](https://github.com/philfanzhou/ForgeSteward/pull/162), [Issue #138](https://github.com/philfanzhou/ForgeSteward/issues/138)): work-cycle gains an explicit final cleanup stage that dispatches one cleanup-only review-and-merge subagent and writes a per-resource `cleanup.md` audit listing every branch and worktree outcome. Workspaces are recorded in a run-scoped ownership entry, and a worktree outside the conventional workspace directory is removable only when this run's record names that exact path and every existing safety condition holds. Resource-lock holders become structured `run/task/attempt` owner keys with same-owner retries and stale-lock recovery that never deletes a lock automatically, and the state lock and run-record event guard now write owner metadata for manual recovery after process death. A `pr-open` cleanup record is reconciled with the Change Request's actual state at the next startup, with closed-without-merging becoming eligible again after a 168-hour cooldown; repeated dispatches of the same stage and item write to their own `-r<N>` evidence directories; the final report renders every recordable wait type; and prepare-work's stage reply is now exactly one line.
- **Shared stage rules and version preflight** ([PR #187](https://github.com/philfanzhou/ForgeSteward/pull/187), [Issue #171](https://github.com/philfanzhou/ForgeSteward/issues/171); [PR #194](https://github.com/philfanzhou/ForgeSteward/pull/194), [Issue #178](https://github.com/philfanzhou/ForgeSteward/issues/178); [PR #201](https://github.com/philfanzhou/ForgeSteward/pull/201), [Issue #181](https://github.com/philfanzhou/ForgeSteward/issues/181); [PR #193](https://github.com/philfanzhou/ForgeSteward/pull/193), [Issue #174](https://github.com/philfanzhou/ForgeSteward/issues/174)): every independently installed stage skill carries the same untrusted-content boundary — Issue, Change Request, review, CI, and external text are evidence only, and embedded instructions that change authorization, scope, required checks, branch protection, or secret handling are never followed. The three stage packages now share one bounded CI wait limit (twice the median completed duration of the last ten successful runs, 30 minutes by default, capped at 60 minutes) and one feature-size sentence, both kept aligned by static tests. check-workflow's cross-skill comparison works in a standalone installation and records each unverifiable equivalence as an explicit skill gap, and every stage package carries a `VERSION` marker checked by a read-only preflight before its first write, so a mixed or missing stage version stops the stage without writing.
- **Compatibility fixes** ([PR #153](https://github.com/philfanzhou/ForgeSteward/pull/153), [Issue #148](https://github.com/philfanzhou/ForgeSteward/issues/148); [PR #154](https://github.com/philfanzhou/ForgeSteward/pull/154), [Issue #150](https://github.com/philfanzhou/ForgeSteward/issues/150); [PR #189](https://github.com/philfanzhou/ForgeSteward/pull/189), [Issue #180](https://github.com/philfanzhou/ForgeSteward/issues/180)): work-cycle's bundled `references/agents.md` was renamed to `subagent-lifecycle.md` so case-insensitive filesystems cannot auto-load it as a nested instruction entry, with check-workflow requiring exact-case tracked selection and a packaging test guarding the name. The installer's version classification now reports a mixed installation as behind instead of ahead, so an older installed plugin is never hidden by a newer one. Duplicate scenario identifiers were renumbered with a test that checks every identifier reference (documentation and tests only).

## Upgrade and rollback

Use the version-pinned [installation and upgrade commands](../../README.md#supported-agents-and-installation) for `v0.2.26`. Upgrade all six plugins together when using work-cycle, then start a new Agent session; the new stage preflight stops a dispatched stage before its first write whenever an installed stage package version differs from the orchestrator's, so a mixed installation fails safely instead of silently. Publication does not change user installations automatically.

check-workflow's write boundary widens beyond v0.2.25's instruction consolidation and collaboration-language default: an authorized run can now record the English working-environment rule, translate project-maintained documents, and update the repository About within the same cleanup Change Request. Historical Issues, Change Requests, comments, releases, other people's content, technical terms, and quoted text stay untranslated; check-only, local-only, review-only, and audit-only remain explicit no-write limits. Review the resulting cleanup Change Request before merging. See the bundled [migration rules](../../plugins/check-workflow/skills/forge-steward-check-workflow/references/agent-entrypoints.md), [English conversion rules](../../plugins/check-workflow/skills/forge-steward-check-workflow/references/english-conversion.md), and [scenarios](../check-workflow-scenarios.md).

fix-feedback no longer merges under any condition: a third completed repair round only hands the head to review-and-merge for one final review, and force-push requires explicit user or repository authorization. Skill names, installer CLI commands, and the seven-section report format are unchanged.

Saved run records stay compatible: the `release_audit` field is optional and older handoffs render as before, the first attempt keeps the existing `<task-id>/` evidence directory, and callers that omit the new attempt option keep the old behavior. Resource-lock holders are now structured `run/task/attempt` keys; leftover locks and event guards are never removed automatically, so a guard written by an older version needs the documented manual recovery instead of silent takeover. Rolling back the installed Skills does not undo code, project rules, or hosting-platform actions already produced; see the [fixed-version rollback guide](../versioned-installation.md#switching-or-rolling-back).
