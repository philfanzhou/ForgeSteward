# v0.2.18

本文件是 `v0.2.18` 的发布输入。远端同名附注 Tag 和非 draft GitHub Release 都存在，才算发布完成。

这一版主要做了两件事：技能汇报和平台留言改用日常中文，不再照搬规则里的内部术语；删掉了允许 Agent 自动升版的规则。

## 改了什么

- **汇报说人话**（[PR #55](https://github.com/philfanzhou/ForgeSteward/pull/55)、[PR #57](https://github.com/philfanzhou/ForgeSteward/pull/57)，对应 [Issue #53](https://github.com/philfanzhou/ForgeSteward/issues/53)）：
  - 6 个技能要求 Agent 汇报的条目，改用日常说法。例如“分诊”改为“归类处理”，“对账”改为“核对”，“门禁”改为“准入条件”，并写明不说“制品”。
  - 每个技能都加了一句：给用户的汇报和写到 Issue、PR 上的文字用日常中文，内部术语必须出现时先解释。
  - `AGENTS.md` 新增「面向用户的输出用语」一节。
  - execute-work 的「最终报告」移到包内新文件 `references/reporting.md`，因为入口文件快到长度上限了。入口写明汇报前要读这个文件。
  - 规则正文里给模型看的内部术语没有改。
- **不准自动升版**（[PR #56](https://github.com/philfanzhou/ForgeSteward/pull/56) 和本次发布 PR）：`AGENTS.md` 和 `docs/releasing.md` 里“版本已发布就自动加一”的规则全部删除。以后只有维护者明确要求才改版本号。
- **删掉一条重复规则**（[PR #54](https://github.com/philfanzhou/ForgeSteward/pull/54)）：`AGENTS.md` 里“提交 PR 不代表获准合并”一句与技能规则重复，已删除。

## 升级需要做什么

技能名、调用方式、安装方式和配置都没变，没有数据迁移。按[固定版本安装、升级与回退](../versioned-installation.md)更新已安装的插件即可；用 work-cycle 时六个插件要升到同一版本。不升级的话，Agent 用的还是旧版说法。

- 本地测试 148 项：142 项通过，6 项因环境不适用而跳过。
- 技能长度检查、版本一致检查（`sync_marketplace.py --check`）、`git diff --check` 通过。
- Claude Code `2.1.283` 对六个插件做 `claude plugin validate`，全部通过。
- 各 PR 的三个系统安装器检查和 discovery 检查全部通过。

没验证的：没有实测各 Agent 的实际输出是否真的不再带内部术语。改的是规则文字，不能保证模型每次都照做，也没有加自动拦截。
