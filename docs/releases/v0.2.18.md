# v0.2.18

This file is release input for `v0.2.18`. Publication is complete only when both the matching remote annotated Tag and a non-draft GitHub Release exist.

This release made two main changes: Skill reports and platform comments switched to everyday Chinese instead of repeating internal rule terminology, and rules permitting automatic version bumps by Agents were removed.

## Changes

- **Plain-language reports** ([PR #55](https://github.com/philfanzhou/ForgeSteward/pull/55), [PR #57](https://github.com/philfanzhou/ForgeSteward/pull/57), [Issue #53](https://github.com/philfanzhou/ForgeSteward/issues/53)):
  - The reporting requirements in all six Skills adopted everyday wording. For example, Chinese technical terms for triage, reconciliation, and gates were replaced with ordinary expressions for classifying and handling items, checking, and entry conditions. Reports were also explicitly told to avoid the formal Chinese term for artifacts.
  - Each Skill added a requirement to write user reports and Issue/PR text in everyday Chinese, explaining any necessary internal terminology first.
  - `AGENTS.md` gained a user-facing wording section.
  - execute-work's final-report rules moved to the new bundled `references/reporting.md` because its entry point was approaching the length limit. The entry explicitly required reading it before reporting.
  - Internal terminology in the rules addressed to the model remained unchanged.
- **No automatic version bumps** ([PR #56](https://github.com/philfanzhou/ForgeSteward/pull/56) and this release PR): `AGENTS.md` and `docs/releasing.md` removed every rule allowing an automatic increment when the current version was already released. Version changes thereafter required an explicit maintainer request.
- **One duplicate rule removed** ([PR #54](https://github.com/philfanzhou/ForgeSteward/pull/54)): the AGENTS.md statement that submitting a PR does not authorize merging duplicated Skill rules and was removed.

## Upgrade steps

Skill names, invocation, installation, and configuration did not change; no data migration was needed. Update installed plugins using [fixed-version installation, upgrades, and rollback](../versioned-installation.md). All six must use the same version for work-cycle. Without upgrading, Agents continue using the older wording.
