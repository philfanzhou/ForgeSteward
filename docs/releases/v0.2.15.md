This file is release input; release is complete only when both the remote Tag of the same name and a non-draft GitHub Release exist. It fixes the description-display problem in [Issue #39](https://github.com/philfanzhou/ForgeSteward/issues/39), adds maintenance constraints, and implements the DeepSeek Harness managed-installation adapter from [Issue #40](https://github.com/philfanzhou/ForgeSteward/issues/40). ## Changes and migration

- Tightened the shared description maintenance budget from 1,024 to 500 UTF-16 units to match the complete-description display boundary in DeepSeek Harness `0.2.0-rc.2`'s default discovery list. Body byte and line budgets are unchanged.
- Shortened prepare-work's description from 707 to 487 units, retaining purpose, excluded cases, single-line Issue output, baseline priority, and the default count. Detailed business rules remain in the original body and references.
- AGENTS.md, the README, and cross-Agent compatibility documentation clarify units, configurability, and validation scope. The budget script and existing three-OS CI checks prevent new or edited descriptions from exceeding the limit again.

Future contributors must move excess description detail into the body or reference files, without relying on increased client display limits or exemptions for particular Skills. Existing users need no client configuration change for this description fix. This version adds list/install/update/status/uninstall in `scripts/deepseek.py`, reusing the shared installation transaction core while preserving the OpenCode contract. See the [DeepSeek documentation](../deepseek-installer.md) for installation maintenance and pinned-source rollback. A complete DeepSeek work cycle is not claimed as delivered.

## Validation and limitations

Added regressions for 500/501-unit descriptions, emoji and mixed characters, CLI rejection, and automatic inclusion of future plugins. Ran the formatter in the local DeepSeek Harness package to check default length, whitespace normalization, and boundaries, confirming complete display of all six descriptions. Earlier isolated Provider validation confirmed all six complete bodies and resource paths; actual Provider revalidation after these changes also passed.

After adding the installation adapter, 148 local unit tests completed: 142 passed and 6 were skipped due to client or platform conditions. Budget checks, marketplace synchronization, prepare-work Skill validation, documentation links, and `git diff --check` passed. PR and final main CI still require verification at delivery and release. Desktop GUI, real subagent stage execution, merge behavior, and model compaction recovery were not certified in this run. Static length checks and formatter validation without model calls do not replace those acceptance checks.

Issue #40 installation-adapter validation also covers complete project/user resources, a path matrix, pinned-commit rollback, ordinary failure/cancellation/rollback failure, locking between two processes, and bounded uninstall exit codes. The real `0.2.0-rc.2` Provider passed checks for all bodies and resourceBase, resource digests, ranking, and rediscovery after actual uninstallation in an isolated macOS root. CI without an explicitly provided runtime skips real Harness tests. Native Windows Harness and model work cycles remain unverified. Three-OS static regressions continue, with OpenCode Linux discovery still pinned to `1.18.30`.
