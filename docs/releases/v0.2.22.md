# v0.2.22

This file is release input for `v0.2.22`. Publication is complete only when both the matching remote annotated Tag and a non-draft GitHub Release exist.

This release centralized README installation, upgrade, and uninstall instructions in one Agent data file. work-cycle gained scripted final reports in a fixed format, a read-only check of other local Agent installations at startup, and installation/upgrades after end-of-run user consent. Subagent CI-log reading, CI waiting, and returns use less context. Before release, intermittent corruption of fake-command call logs in Windows installation tests was also fixed. Review standards, merge conditions, and the three-repair limit per PR remained unchanged.

## Changes

- **One Agent-data source for installation instructions** ([PR #101](https://github.com/philfanzhou/ForgeSteward/pull/101), [Issue #94](https://github.com/philfanzhou/ForgeSteward/issues/94)): work-cycle adds `scripts/agents.json` with install/update/uninstall commands for Claude Code, Codex, ZCode, OpenCode, and DeepSeek Harness. README installation was reorganized by Agent; tests compare it with `VERSION`, plugin directories, and the data file. ZCode now uses a GitHub address plus version Tag directly as its marketplace source.
- **Fixed final report format** ([PR #100](https://github.com/philfanzhou/ForgeSteward/pull/100), [Issue #95](https://github.com/philfanzhou/ForgeSteward/issues/95)): new `run_record.py report` renders seven sections from run-directory `handoff.json` and events, with seven fixed result terms and field-by-field errors for missing/invalid data. `references/report.md` defines the format once, with a manual fallback when the script cannot run.
- **Check other Agent installations at startup** ([PR #102](https://github.com/philfanzhou/ForgeSteward/pull/102), [Issue #97](https://github.com/philfanzhou/ForgeSteward/issues/97)): new `scripts/agent_install.py check` reads installed ForgeSteward versions, compares them with latest stable, and includes results in report section seven. An inaccessible Agent does not affect the others.
- **Install or upgrade after consent** ([PR #103](https://github.com/philfanzhou/ForgeSteward/pull/103), [Issue #98](https://github.com/philfanzhou/ForgeSteward/issues/98)): ask once at report end when an Agent has missing, incomplete, or older Skills; after consent use `agent_install.py apply`. Target version and Agent list are required. Only one installation may run at a time; never downgrade. OpenCode/Harness source must match the Release commit; one Agent's failure does not stop the others.
- **Replace plugin sources whether present or absent** ([PR #107](https://github.com/philfanzhou/ForgeSteward/pull/107), [Issue #104](https://github.com/philfanzhou/ForgeSteward/issues/104)): Claude Code, Codex, and ZCode list marketplaces before mutation, remove an old source only when it exists, then add the target. If listing fails, that Agent is unchanged. This fixes installation when all plugins were absent but an old source remained.
- **Retain results after installation errors** ([PR #108](https://github.com/philfanzhou/ForgeSteward/pull/108), [Issue #106](https://github.com/philfanzhou/ForgeSteward/issues/106)): file errors after mutation no longer return exit 2, which meant no changes, or discard per-Agent results. Failed temporary/lock directory cleanup returns 1 with recovery instructions. A stop before any mutation returns 3.
- **Stable Windows installation-test logs** ([PR #111](https://github.com/philfanzhou/ForgeSteward/pull/111), [Issue #110](https://github.com/philfanzhou/ForgeSteward/issues/110)): fake commands write separate temporary files, then atomically publish complete call records. Unpublished leftovers are excluded from assertions; corrupt published records still fail tests. CI runs the target Windows case ten consecutive times.
- **Reduced context use** ([PR #105](https://github.com/philfanzhou/ForgeSteward/pull/105), [Issue #99](https://github.com/philfanzhou/ForgeSteward/issues/99)): execute-work, fix-feedback, and review-and-merge add identical `references/ci.md`. Read failed steps first and expand only as needed; discard repetitive CI-wait output and inspect results. The requirement to reread to EOF applies only to Skill rules. work-cycle subagent returns contain only result, link, reason, next step, and evidence location.

## Upgrade steps

Skill names and invocation did not change; no data migration was needed. Follow each Agent's README upgrade instructions for `v0.2.22`. All six plugins must use the same version for work-cycle.

Behavioral changes:

- ZCode's recommended installation adds a marketplace directly from a GitHub version Tag, without a local clone. Existing local-source installations can uninstall/reinstall using README.
- work-cycle reads local Agent installation state at startup without changing configuration. Installation/upgrades happen only after the final report asks and receives your consent.
- work-cycle's final report in this release uses seven fixed sections.
