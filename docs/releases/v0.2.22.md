# v0.2.22

本文件是 `v0.2.22` 的发布输入。远端同名附注 Tag 和非 draft GitHub Release 都存在，才算发布完成。

这一版主要做了四件事：用一份数据文件统一维护 README 中各 Agent 的安装、升级、卸载说明；work-cycle 的最终汇报改为由脚本按固定格式生成；work-cycle 开始时只读检查本机其他 Agent 的安装情况，结束后经用户同意可以安装或升级；减少子 Agent 读 CI 日志、等 CI 和交回结果时占用的上下文。审查标准、合并条件和“每个 PR 最多改 3 次”都没变。

## 改了什么

- **安装说明来自同一份 Agent 数据**（[PR #101](https://github.com/philfanzhou/ForgeSteward/pull/101)，[Issue #94](https://github.com/philfanzhou/ForgeSteward/issues/94)）：work-cycle 技能包新增 `scripts/agents.json`，列出 Claude Code、Codex、ZCode、OpenCode、DeepSeek Harness 的安装、升级、卸载命令。README 重写安装部分，每个 Agent 一节；测试校验 README 与 `VERSION`、插件目录和数据文件一致。ZCode 改为直接用 GitHub 地址加版本 Tag 作为市场来源。
- **最终汇报固定格式**（[PR #100](https://github.com/philfanzhou/ForgeSteward/pull/100)，[Issue #95](https://github.com/philfanzhou/ForgeSteward/issues/95)）：`run_record.py` 新增 `report` 子命令，根据运行目录的 `handoff.json` 和事件记录生成 7 个章节的汇报，结果只用 7 个固定说法；数据缺字段或用词不对时逐条指出。格式只在 `references/report.md` 定义一处，脚本无法运行时有手写兜底。
- **开始时检查其他 Agent 的安装情况**（[PR #102](https://github.com/philfanzhou/ForgeSteward/pull/102)，[Issue #97](https://github.com/philfanzhou/ForgeSteward/issues/97)）：新增 `scripts/agent_install.py check`，只读查询各 Agent 装的 ForgeSteward 版本，和最新正式版比较，结果写进汇报第 7 节。单个 Agent 查不了不影响其他。
- **经同意后安装或升级**（[PR #103](https://github.com/philfanzhou/ForgeSteward/pull/103)，[Issue #98](https://github.com/philfanzhou/ForgeSteward/issues/98)）：有缺少、不完整或落后的 Agent 时，汇报末尾询问一次；用户同意后由 `agent_install.py apply` 处理。必须给出目标版本和 Agent 名单；同一时间只允许一个安装；不降级；OpenCode 和 DeepSeek Harness 使用的源码要与 Release 的提交一致；一个 Agent 失败不影响其他。
- **插件来源无论在不在都换对**（[PR #107](https://github.com/philfanzhou/ForgeSteward/pull/107)，[Issue #104](https://github.com/philfanzhou/ForgeSteward/issues/104)）：Claude Code、Codex、ZCode 改动前先列出市场，旧来源存在才删除，再添加目标版本；列不出市场时这个 Agent 不做改动。修复了“插件都没装、但留着旧版本来源”时安装失败的问题。
- **安装中途出错时保留结果**（[PR #108](https://github.com/philfanzhou/ForgeSteward/pull/108)，[Issue #106](https://github.com/philfanzhou/ForgeSteward/issues/106)）：开始改动后出现文件错误，不再返回表示“没有改动”的退出码 2，也不再丢掉各 Agent 的结果；删不掉临时目录或锁目录时返回 1 并说明怎么处理；还没改动就停下时返回 3。
- **减少上下文占用**（[PR #105](https://github.com/philfanzhou/ForgeSteward/pull/105)，[Issue #99](https://github.com/philfanzhou/ForgeSteward/issues/99)）：execute-work、fix-feedback、review-and-merge 新增内容相同的 `references/ci.md`，规定先读失败步骤、按需扩大范围，等 CI 时丢掉反复刷新的输出只看结果；“补读到文件末尾”只适用于技能规则文件；work-cycle 规定子 Agent 交回时只写结果、链接、原因、下一步、证据位置五项。

## 升级需要做什么

技能名和调用方式没变，没有数据迁移。按 README 中各 Agent 的升级步骤更新到 `v0.2.22`；用 work-cycle 时六个插件要升到同一版本。

行为上的变化：
- ZCode 的推荐安装方式改为直接从 GitHub 版本 Tag 添加市场，不再需要本地仓库副本；原来用本地副本安装的可以按 README 卸载后重装。
- work-cycle 开始时会只读查询本机各 Agent 的安装情况（不改任何配置）；只有在最终汇报中提问并得到你的同意后，才会安装或升级。
- work-cycle 的最终汇报改为固定的 7 个章节。

## 验证情况

- 本地测试 233 项：227 项通过，6 项因环境不适用而跳过。
- 技能长度检查、版本一致检查（`sync_marketplace.py --check`）、`git diff --check` 通过。
- 各 PR 的三个系统安装器检查和 discovery 检查全部通过；本次 7 个 PR 均经 review-and-merge 技能逐项审查后合并。
- `agent_install.py` 的检查和安装都用临时目录和假命令测试；开发期间在本机只读运行过 `check`，结果与实际安装一致。

没验证的：`apply` 没有在真实 Agent 上端到端测过；ZCode 桌面界面添加市场、原生 Windows 下的 OpenCode 和 DeepSeek Harness 没有实测；不能保证模型每次都照做。
