# v0.2.27

This file is release input for `v0.2.27`. Publication is complete only when both the matching remote annotated Tag and a non-draft GitHub Release exist.

This release completes the English working-environment guidance for future commit messages, makes subagent waiting and stage-time accounting cheaper and more accurate, distinguishes resource-lock errors from contention, classifies CI failures without resetting check budgets, requires authoritative sources for blocking acceptance criteria, adds a complete detached-workspace ownership and safe-reclamation lifecycle, and lets work-cycle reuse validated capabilities and load complete stage rules in bounded groups while retaining verifiable rule packages for the whole run. All six plugins move together to `0.2.27`.

## Changes

- **English working environment for commit messages** ([PR #216](https://github.com/philfanzhou/ForgeSteward/pull/216)): this repository's `AGENTS.md` gains the fixed English working-environment section, extending the existing documentation and collaboration-language rules to future commit messages, with explicit maintainer overrides and preservation of historical and technical text. All original `AGENTS.md` bytes are retained and no workflow rule was removed.
- **Subagent waiting and stage-time accounting** ([PR #217](https://github.com/philfanzhou/ForgeSteward/pull/217), [Issue #207](https://github.com/philfanzhou/ForgeSteward/issues/207); [PR #219](https://github.com/philfanzhou/ForgeSteward/pull/219), [Issue #206](https://github.com/philfanzhou/ForgeSteward/issues/206)): work-cycle prefers bounded event and cursor waits over repeated unchanged polling, persists compact scheduling state across user updates, and falls back to bounded snapshot backoff when events are unavailable; warnings, timeouts, and actual failures keep their separate outcomes. Stage time is now measured per attempt through schema-2 events with attempt and event identities: completed active intervals are summed, running and suspended attempts stay explicit, identical retries append once, and unmatched or ambiguous legacy transitions produce incomplete-accounting diagnostics instead of inflated Review and Cleanup numbers. Reports distinguish elapsed wall time, accumulated completed stages, the active interval union, suspension, and overlapping waits; unambiguous legacy reports and event files remain unchanged, and older readers can miscount new events.
- **Resource-lock error classification** ([PR #218](https://github.com/philfanzhou/ForgeSteward/pull/218), [Issue #205](https://github.com/philfanzhou/ForgeSteward/issues/205); [PR #225](https://github.com/philfanzhou/ForgeSteward/pull/225)): lock acquisition gains opt-in, versioned JSON results for acquired, held, busy, and error outcomes while preserving the legacy CLI text and exit codes, so permission and I/O failures are no longer reported as contention. Waits are validated before retrying and capacity mismatches are reported with the correcting argument; stage dispatch requires complete commands with explicit capacities and begins a recorded resource wait only for a busy result. PR #225 reworks the regression fixtures so timing assertions no longer patch Python's shared `time` module, fixing an intermittent macOS failure where subprocess timeout polling called the mock.
- **CI failure classification without resetting check budgets** ([PR #220](https://github.com/philfanzhou/ForgeSteward/pull/220), [Issue #208](https://github.com/philfanzhou/ForgeSteward/issues/208)): the three independently installed stage packages share one phase and evidence table that distinguishes proved external causes from deterministic code or configuration failures and keeps unknown causes explicit. Implementation, review, repair, and both merge-lane paths save and restore the original deadline, head, required checks, and retry history, so stage switches, new heads, and reruns cannot restart the budget or create another unrelated retry; a cancelled final container startup stays unverified. The numeric wait calculation is unchanged.
- **Authoritative sources for blocking acceptance criteria** ([PR #221](https://github.com/philfanzhou/ForgeSteward/pull/221), [Issue #212](https://github.com/philfanzhou/ForgeSteward/issues/212)): prepare-work no longer treats an agent's optional rollback recommendation as a required blocker. Each blocking criterion needs an exact user or Issue source, an applicable policy location, or a demonstrated technical prerequisite; suggestions stay separate while genuine policy and prerequisite gaps still block. Correcting an invented blocker updates the original handoff and resumes from valid audits, commits, checks, and review counts.
- **Detached workspace ownership and safe reclamation** ([PR #222](https://github.com/philfanzhou/ForgeSteward/pull/222), [Issue #209](https://github.com/philfanzhou/ForgeSteward/issues/209); [PR #223](https://github.com/philfanzhou/ForgeSteward/pull/223), [Issue #210](https://github.com/philfanzhou/ForgeSteward/issues/210)): workspace ownership records accept explicit detached identities — `branch: null`, `detached: true`, and a full Git object ID in `head` — while attached records keep their real branch; incomplete legacy identities return clear retention reasons and contradictory or changed identities cannot authorize removal. A finished detached stage workspace can be reclaimed only when it is explicitly owned, disposable, finished, has an exact head, complete saved evidence, confirmed inactivity, reviewed ignored files, a supported lifecycle, and durable recovery. The inventory stays read-only, combines live Git facts with cleanup's separate `disposal.json`, reports every failed condition and the retained count, and distinguishes ordinary no-force Git removal from a supported host archive; every detached workspace otherwise stays ineligible for removal.
- **Resource-scope measurement** ([PR #224](https://github.com/philfanzhou/ForgeSteward/pull/224), [Issue #215](https://github.com/philfanzhou/ForgeSteward/issues/215)): a bounded disposable experiment and decision report document how two repositories independently acquire capacity-1 locks while sharing one identity — three simulated identity collisions across the trials with zero in the controls — recording per-trial CPU, wall time, memory, and overlap, and comparing existing repository locks with a separately authorized shared coordinator. Production helpers, rules, user configuration, and installed clients are unchanged; no historical-cause or production-throughput claim is made.
- **Run-scoped capability reuse** ([PR #226](https://github.com/philfanzhou/ForgeSteward/pull/226), [Issue #211](https://github.com/philfanzhou/ForgeSteward/issues/211)): later stages can reuse an already validated environment method through one optional run-scoped capability record with safe adapter identities, explicit freshness, cheap validation, and orchestrator-only aggregation. Permission gaps stay uncovered and mutable request or check state still requires current reads; startup, lifecycle, and run-record rules require the complete reference.
- **Bounded rule loading and retained rule packages** ([PR #227](https://github.com/philfanzhou/ForgeSteward/pull/227), [Issue #213](https://github.com/philfanzhou/ForgeSteward/issues/213); [PR #228](https://github.com/philfanzhou/ForgeSteward/pull/228), [Issue #214](https://github.com/philfanzhou/ForgeSteward/issues/214)): work-cycle now plans complete UTF-8 ranges for required rule files within a caller-supplied byte allowance — including framing and reserved wrapper space — so several files sharing one tool response cannot be silently truncated in aggregate. Caller-attested receipts track observed ranges, recovery re-reads only missing sections, changed rules invalidate coverage, and a new context identifier clears coverage after compaction; a one-file section fallback remains for unknown allowances and independently installed stages. The run also retains all six resolved rule packages in its Git metadata with pinned paths, versions, and resource hashes, validating the complete retained set before a stage writes, so an external plugin refresh that removes a package cache mid-run cannot make a later helper call disappear or silently use a different package. Where retention is unsupported, a mandatory reference explains explicit coherent recovery preserving attempts, review rounds, heads, completed writes, and original wait deadlines.

## Upgrade and rollback

Use the version-pinned [installation and upgrade commands](../../README.md#supported-agents-and-installation) for `v0.2.27`. Upgrade all six plugins together when using work-cycle — the stage preflight stops a dispatched stage before its first write whenever an installed stage package version differs from the orchestrator's, and startup now also requires complete package retention where supported. Start a new Agent session after upgrading. Publication does not change user installations automatically.

Saved run records stay compatible: schema-2 attempt events are written by new runs while existing unambiguous legacy reports and event files render as before; capability records, detached identity fields, and `disposal.json` are optional additions, and callers that omit them keep the old behavior. Older readers can miscount schema-2 events, so rolling a run record back to an older orchestrator requires a matching reader and retained originals; leftover locks, event guards, and retained packages follow the documented manual recovery and run-directory lifetime instead of silent takeover. Detached workspaces without a complete ownership identity are retained, never removed. The `AGENTS.md` change affects this repository's own conventions only and adds text without replacing any rule. Skill names, installer CLI commands, and report formats are otherwise unchanged. Rolling back the installed Skills does not undo code, project rules, or hosting-platform actions already produced; see the [fixed-version rollback guide](../versioned-installation.md#switching-or-rolling-back).
