## Changes since v0.2.7

From [PR #26](https://github.com/philfanzhou/ForgeSteward/pull/26).

### review-and-merge (post-merge completion)

- Added a local main-branch update step: if a local main branch exists, fetch the remote and run `git merge --ff-only <remote>/<main-branch>` (such as `origin/main`) in a workspace with that branch checked out and no uncommitted changes. Do not run it on other branches. If there are uncommitted changes or fast-forward is impossible, preserve the state and report it; do not reset or force an overwrite.
- Rejection by `git branch -d` is not evidence that a branch is unmerged; this is common after squash or rebase merges. Force-delete only after confirming the platform's merged state and that the local branch head matches the merged Change Request head. Preserve and report mismatches.
- Run `git worktree prune` after removing a worktree to clean up stale records.
- Former steps 3 and 4 in post-merge completion become steps 4 and 5.

### execute-work

- Added renaming to the examples of prohibited incidental refactoring.
- For target designs delivered as documentation, secret scanning, like format checks, link checks, and existing green CI, is not evidence of semantic correctness.

## Migration

- There are no incompatible changes; installation IDs and invocation methods are unchanged.
- After merging, review-and-merge fast-forwards the local main branch when conditions are met and may force-delete local branches from the current run that are confirmed merged. It makes no such changes when the main-branch workspace has uncommitted work or a local branch head differs from the merged head.

## Installation, upgrade, and rollback

Use these commands only after confirming this version has been released, in a new environment without a marketplace of the same name. For an existing installation, follow the [version switching and cleanup guide](../versioned-installation.md) to record the selected subset, scope, and source; uninstall old copies, replace the marketplace ref, and reinstall the original subset. Do not add the same marketplace twice or edit caches directly. The guide's `v0.2.1` / `find-work` examples are historical; for this version, replace both with `v0.2.8` and the actual plugin names in the table above.

Example for a new Codex environment (install other plugins individually using the table above):

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.8
codex plugin add review-and-merge@forge-steward
codex plugin list
```

Example for a new Claude Code environment:

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.8
/plugin install review-and-merge@forge-steward
```

For OpenCode, use a separate snapshot and replace the absolute placeholder paths below. Run installation commands from the target repository you want to maintain:

```bash
git clone --branch v0.2.8 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.8
git -C /absolute/path/ForgeSteward-v0.2.8 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.8/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.8/scripts/opencode.py status --all --project .
```

Before installing, confirm that the checkout SHA matches the Release. For an existing installation, use `update --all --project .` from the same snapshot's installer, or specify the recorded subset and `--user`, instead of repeating `install`. If local customizations trigger protection, back them up and inspect them before deciding what to do; do not force an overwrite.

For ZCode, follow [fixed versions and rollback](../zcode.md#fixed-versions-and-rollback) to add the root of the verified, separate `v0.2.8` checkout as a local marketplace, select the plugin subset, and confirm the installed versions. Before switching, save the original source, uninstall old plugins, and remove the old marketplace. Do not directly reuse Codex's `--ref` or Claude's `@tag` syntax.

Upgrading from `v0.2.7` requires only switching versions, with no additional migration. From `v0.2.6` or earlier, first read the [v0.2.7 migration notes](v0.2.7.md#migration): check-workflow's deletion behavior is an incompatible change. From `v0.2.1` or earlier, first remove retired `find-work` and install `prepare-work` instead. Confirm every selected plugin is `0.2.8`. Roll back with the same procedure by selecting the retained `v0.2.7`; rollback does not undo project changes, merges, or hosting-platform operations already performed.

## Validation and exclusions

Before release, run the full unit suite, unified-version, marketplace, resource, and format validation, and relative-link checks. The installer checks on all three operating systems and the pinned OpenCode discovery check must pass for both the PR and final main commit. Record actual results in the PR / Release.

E14–E15 and R07–R10 are manual rule walkthroughs, not independent Agent model-behavior evaluations. review-and-merge was not actually run to validate local main-branch fast-forwarding or force-deletion of branches. ZCode remains a development preview; GUI marketplace lifecycle and model behavior are not validated by these checks.

This release distributes only a Git snapshot and GitHub's automatic source archives, with no separate build packages. It does not change real local installations or user configuration.
