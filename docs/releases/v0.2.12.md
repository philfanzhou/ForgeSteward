## 原因与修复

用户报告 `Skill … exceeded the main prompt context limit and was truncated.`。与该告警匹配的 Codex 上游实现，将所选技能主提示词按 UTF-8 字节边界截到 8,000 字节后注入模型，超出时发出警告；这是单个技能主提示词的限制，不是发现列表的描述预算，也不是模型整个上下文窗口已满。核对源码基线为 `d7d9f2b9b53b53568b30c4dea7e095ec276ebe9c`：

- [render.rs 的预算与截断实现](https://github.com/openai/codex/blob/d7d9f2b9b53b53568b30c4dea7e095ec276ebe9c/codex-rs/ext/skills/src/render.rs)
- [extension.rs 的注入与告警](https://github.com/openai/codex/blob/d7d9f2b9b53b53568b30c4dea7e095ec276ebe9c/codex-rs/ext/skills/src/extension.rs)

原 prepare-work 入口为 17,800 字节，截断后无法完整注入后续 ready、交接和输出规则。原文件仍存在，模型可以通过工具补读，但不能把这当作自动保证。[官方技能文档](https://developers.openai.com/zh-Hans/docs/build-skills)介绍了通过入口、引用和资源逐步加载技能的方式。

- 入口缩为 4,120 字节，保留目标、授权、最终输出契约，新增按阶段加载要求。
- 原有详细规则移到技能内的四个文件：队列与分诊、ready 门禁、阻塞推进、交接与恢复；原有业务规则保留，跨文件引用改为相对链接。
- 路径基于实际安装的技能目录解析。工具返回截断时分段补读；文件缺失或不可读时说明影响，不凭摘要继续受影响的准备或入选判定。
- CI 对 prepare-work 入口和每个引用文件设 6,000 字节维护预算，为当前 8,000 字节入口上限留出余量；引用文件预算用于控制读取规模，不宣称是工具的通用限制。同时验证引用可达性及安装后资源内容一致。

## 迁移与使用

安装 ID、调用名称、description 和默认 prompt 不变。必须安装完整技能目录，包括 `references/`；只复制 `SKILL.md` 无法执行完整流程。发布确认后按[版本切换指南](../versioned-installation.md)升级已选插件并开始新会话；不直接改写旧版本缓存。本次源码修改不自动升级本机安装。

旧版本临时恢复时，可明确要求 Agent 从实际安装路径分段读取完整 `SKILL.md`，确认读到末尾后再准备。该操作补充当前会话上下文，不消除旧入口在下次调用时的截断警告。
