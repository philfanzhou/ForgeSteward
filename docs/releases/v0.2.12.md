# ForgeSteward v0.2.12

This file is release input for an unreleased target and does not mean it has been published. Compared with `v0.2.11`, this fixes main-prompt overflows when Codex invokes prepare-work, check-workflow, and review-and-merge, and leaves headroom for execute-work and fix-feedback, which were near the limit. Business workflows, authorization boundaries, and output contracts are unchanged.

## Cause and fix

A user reported `Skill … exceeded the main prompt context limit and was truncated.` The matching upstream Codex implementation truncates the selected Skill's main prompt at a UTF-8 boundary within 8,000 bytes before injecting it into the model, warning on overflow. This limits a single Skill's main prompt; it is neither the discovery-list description budget nor an indication that the model's entire context window is full. The checked source baseline is `d7d9f2b9b53b53568b30c4dea7e095ec276ebe9c`:

- [Budget and truncation implementation in render.rs](https://github.com/openai/codex/blob/d7d9f2b9b53b53568b30c4dea7e095ec276ebe9c/codex-rs/ext/skills/src/render.rs)
- [Injection and warning in extension.rs](https://github.com/openai/codex/blob/d7d9f2b9b53b53568b30c4dea7e095ec276ebe9c/codex-rs/ext/skills/src/extension.rs)

The original prepare-work entry point was 17,800 bytes; truncation prevented full injection of later readiness, handoff, and output rules. The original file remains available for the model to read through tools, but this cannot be treated as an automatic guarantee. The [official Skill documentation](https://developers.openai.com/zh-Hans/docs/build-skills) describes progressive loading through entry points, references, and resources.

- Reduced the entry point to 4,120 bytes while preserving goals, authorization, and the final output contract, and added requirements to load rules by stage.
- Moved the detailed rules into four files within the Skill: queue and classification, readiness gate, blocker advancement, and handoff and recovery. Existing business rules are preserved, with cross-file references converted to relative links.
- Resolve paths from the actual installed Skill directory. Read truncated tool output in additional segments. If a file is missing or unreadable, explain the impact and do not continue affected preparation or selection decisions based on a summary.
- CI sets a 6,000-byte maintenance budget for every Skill entry point, leaving headroom under the current 8,000-byte entry limit. Reference files share an 8,000-byte chunk-reading budget, without claiming it is a universal tool limit. All Skills validate reachable references and byte-for-byte consistency of complete installed resources.

## Entry-point checks for all Skills

Checks use the UTF-8 byte count of the complete `SKILL.md`, including frontmatter, rather than character or token counts:

| Skill | Original entry bytes | Original state | Bytes after fix |
| --- | ---: | --- | ---: |
| `check-workflow` | 8,424 | Exceeded 8,000 bytes | 5,291 |
| `prepare-work` | 17,800 | Exceeded 8,000 bytes | 4,120 |
| `execute-work` | 7,881 | Only 119 bytes remaining | 5,805 |
| `review-and-merge` | 11,533 | Exceeded 8,000 bytes | 5,096 |
| `fix-feedback` | 7,946 | Only 54 bytes remaining | 5,305 |

check-workflow moves inspection, deletion, and submission steps into `references/procedure.md`, reads the existing policy catalog before inspection, and checks other Skills' reference files when examining them. review-and-merge moves freezing and per-item review into `references/review.md` and post-merge actions into `references/post-merge.md`; it reads the former before reviewing and the latter before merging, while merge gates remain in the entry point. execute-work and fix-feedback move implementation/submission and per-item repair details respectively into reference files, read before the corresponding stage. All entry points retain authorization and final-output requirements. Relative-path, truncated-read, missing-file, and context-recovery rules are distributed independently with each Skill.

Reference files are read through tools and are not automatically clipped by the `SKILL.md` injection limit. Tools can still truncate their own output, so each entry point requires completeness checks and additional reads. The existing check-workflow policy catalog is 7,716 bytes and remains unchanged; the entry-point budget is not incorrectly applied to it.

## Compatibility constraints for future changes

Added the [cross-Agent Skill compatibility agreement](../skill-compatibility.md), checking entry-point, metadata, tool-output, and compaction-recovery differences across four Agents. AGENTS.md requires the same read-only checker for changes. `scripts/check_skill_limits.py` centrally maintains entry/reference byte and line budgets, description UTF-16 length, and reachable references, automatically covering new Skills; CI runs it on three operating systems. Corrected the previous assumption of a 100 KiB ZCode body limit and added optional real CLI probes for the complete-file 100,000-byte boundary and description UTF-16 boundaries.

## Migration and use

Installation IDs, invocation names, descriptions, and default prompts are unchanged. Install the complete Skill directory, including `references/`; copying only `SKILL.md` cannot support the full workflow. After release is confirmed, upgrade selected plugins using the [version-switching guide](../versioned-installation.md) and start a new session. Do not directly rewrite old-version caches. This source change does not automatically upgrade local installations.

For temporary recovery on an old version, explicitly ask the Agent to read the complete `SKILL.md` from its installed path in segments, confirm it has reached the end, and read relevant references before proceeding. This supplements the current session's context but does not eliminate truncation warnings from the old entry point on the next invocation.
