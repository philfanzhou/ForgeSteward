# ForgeSteward v0.2.11

统一 patch 发布：prepare-work 优先用存量 Issue 填满批次，每轮复查存量阻塞并核对子项已全关的父项；四个处理 Issue 的技能对邻近缺陷改为归并登记，减少新开 Issue。本文件是发布输入，不单独证明已发布；执行安装前须确认远端 `v0.2.11` Tag 与非 draft 的 [GitHub Release](https://github.com/philfanzhou/ForgeSteward/releases/tag/v0.2.11) 均存在。实际完整提交 SHA、发布 PR 和最终主线 CI 链接记录在 Release 正文。

## 相对 v0.2.10 的变化

来自 [PR #33](https://github.com/philfanzhou/ForgeSteward/pull/33)。

### prepare-work

- 区分存量与周期新增：周期基线时已开放的 Issue 为存量，从存量拆分出的 task 及为解除存量真实前置而新建并已建立依赖关联的 task 继承存量身份；周期基线跨轮沿用 tracker 或上轮交接记录，不因重跑重置。
- 批次按层级填充：存量 task（主线在前）→ 周期新增中需立即处置的严重风险 → 其余周期新增；前一层处理完才准备下一层，入选数超过上限时优先保留上层项，最终列表按层级输出。删除“在上限内输出尽可能多的 ready 项”的目标表述。
- 新增「存量阻塞复查」：存量候选不因阻塞标记或上轮结论在分诊中排除；每轮核对依赖实际状态与解除条件并移除过时阻塞；只表达排期先后的关联按授权改为非阻塞；依赖未合并前置的存量项本轮仍完成准备；需要维护者动作时写明动作、负责角色及可解除的存量 task。
- 邻近发现归并登记：同类缺陷归并为一个 Issue 或追加到已有同类 Issue，可选改进、推测性风险和整洁问题只在原 Issue 记录；ready 门禁不再要求每个邻近发现先新建 Issue。
- 分诊中核对子项已全部关闭的父项：验收有证据满足时按授权结项并单列，差额拆出的 task 继承存量身份。
- 在既有 tracker 记录周期基线、存量剩余及入选数、本轮新建 Issue 数、周期新增入选数和父级结项数。
- 新增场景 P22–P28。

### execute-work、review-and-merge、fix-feedback

- 独立既有缺陷同类归并到已有或同一个 Issue 追加证据，只有已确认可复现、独立且无同类登记的缺陷才新建；可选改进只在原 Issue 或 Change Request 记录。

## 迁移说明

- 无不兼容变化，不改安装 ID、调用方式或最终输出格式。
- prepare-work 的最终列表可能少于以往：存量候选处理完之前不再用周期新增补位；过程中会说明存量未能填满批次的原因。
- 首次使用本版本且仓库没有清理周期记录时，prepare-work 以本轮冻结时间建立周期基线，此前已开放的全部 Issue 视为存量。
- 在明确调用且未限制写入时，prepare-work 可能移除过时的阻塞标记、把只表达排期先后的依赖改为非阻塞，并关闭验收已满足的父项；需要保持只读时在调用时说明。

## 安装、升级与回退

以下命令仅在本版本发布确认后使用，适用于尚未配置同名市场的新环境。已有安装先按 [版本切换与清理指南](../versioned-installation.md) 记录所选子集、作用域和来源，卸载旧副本并替换市场 ref，再安装原子集；不要重复添加同名市场或直接修改缓存。指南中 `v0.2.1` / `find-work` 是历史示例，本版本必须同时换成 `v0.2.11` 和上表实际插件名。

Codex 新环境示例（其他插件按上表逐项安装）：

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.11
codex plugin add prepare-work@forge-steward
codex plugin list
```

Claude Code 新环境示例：

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.11
/plugin install prepare-work@forge-steward
```

OpenCode 使用独立快照，替换以下占位绝对路径；安装命令从要维护的目标仓库执行：

```bash
git clone --branch v0.2.11 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.11
git -C /absolute/path/ForgeSteward-v0.2.11 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.11/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.11/scripts/opencode.py status --all --project .
```

先核对 checkout SHA 与 Release 一致再安装；已有安装使用同快照安装器的 `update --all --project .`（或按记录指定子集和 `--user`），不是重复 `install`。本地定制触发保护时先备份、核对再决定，不强制覆盖。

ZCode 按 [固定版本与回退](../zcode.md#固定版本与回退) 将已核对的 `v0.2.11` 独立 checkout 根目录加入本地市场，选择插件子集并核对实际安装版本。切换前保存原来源、卸载旧插件并移除旧市场；不直接套用 Codex 的 `--ref` 或 Claude 的 `@tag` 输入。

从 `v0.2.10`、`v0.2.9`、`v0.2.8` 或 `v0.2.7` 升级只需切换版本，无额外迁移；从 `v0.2.6` 或更早版本升级，先阅读 [v0.2.7 迁移说明](v0.2.7.md#迁移说明)，其中 check-workflow 的删除行为是不兼容变化；从 `v0.2.1` 或更早版本升级，先移除退役 `find-work`，改装 `prepare-work`。所有已选插件均核对为 `0.2.11`。回退按相同步骤选择仍保留的 `v0.2.10`；回退不撤销已产生的项目改动、合并或托管平台操作。
