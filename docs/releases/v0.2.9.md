## Changes since v0.2.8

From [PR #28](https://github.com/philfanzhou/ForgeSteward/pull/28).

### prepare-work

- Quantity rule: 10 remains the default limit, but the goal is now to return as many ready items as possible within it. A user-specified count takes precedence. Once mainline work is ready or truly blocked, continue preparing the remaining frozen candidates in order until the limit or requested count is reached, or all remaining candidates are ruled out with recorded reasons.
- Do not stop after finding only one or two ready items. Candidates missing audits, acceptance criteria, ownership of adjacent findings, template fields, or other information that can be completed within authorization must be completed before deciding eligibility.
- The rule against padding the list remains: do not lower gates, split an Issue that should stay unified, create work merely to increase the count, or include Issues appearing after the queue was frozen. When fewer than the limit are selected, explain during work why the other candidates were not selected. Final output remains only a single-line list.
- Clarified continued progress on mainline blockers: prioritizing mainline work does not mean returning only mainline items.

## Migration

- There are no incompatible changes; installation IDs, invocation methods, and the final output format are unchanged.
- One invocation prepares more candidates, so time spent and writes to Issues may increase. Specify a count when invoking the Skill if a smaller batch is needed.

## Installation, upgrade, and rollback

Use these commands only after confirming this version has been released, in a new environment without a marketplace of the same name. For an existing installation, follow the [version switching and cleanup guide](../versioned-installation.md) to record the selected subset, scope, and source; uninstall old copies, replace the marketplace ref, and reinstall the original subset. Do not add the same marketplace twice or edit caches directly. The guide's `v0.2.1` / `find-work` examples are historical; for this version, replace both with `v0.2.9` and the actual plugin names in the table above.

Example for a new Codex environment (install other plugins individually using the table above):

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.9
codex plugin add prepare-work@forge-steward
codex plugin list
```

Example for a new Claude Code environment:

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.9
/plugin install prepare-work@forge-steward
```

For OpenCode, use a separate snapshot and replace the absolute placeholder paths below. Run installation commands from the target repository you want to maintain:

```bash
git clone --branch v0.2.9 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.9
git -C /absolute/path/ForgeSteward-v0.2.9 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.9/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.9/scripts/opencode.py status --all --project .
```

Before installing, confirm that the checkout SHA matches the Release. For an existing installation, use `update --all --project .` from the same snapshot's installer, or specify the recorded subset and `--user`, instead of repeating `install`. If local customizations trigger protection, back them up and inspect them before deciding what to do; do not force an overwrite.

For ZCode, follow [fixed versions and rollback](../zcode.md#fixed-versions-and-rollback) to add the root of the verified, separate `v0.2.9` checkout as a local marketplace, select the plugin subset, and confirm the installed versions. Before switching, save the original source, uninstall old plugins, and remove the old marketplace. Do not directly reuse Codex's `--ref` or Claude's `@tag` syntax.

Upgrading from `v0.2.8` or `v0.2.7` requires only switching versions, with no additional migration. From `v0.2.6` or earlier, first read the [v0.2.7 migration notes](v0.2.7.md#migration): check-workflow's deletion behavior is an incompatible change. From `v0.2.1` or earlier, first remove retired `find-work` and install `prepare-work` instead. Confirm every selected plugin is `0.2.9`. Roll back with the same procedure by selecting the retained `v0.2.8`; rollback does not undo project changes, merges, or hosting-platform operations already performed.
