## 相对 v0.2.8 的变化

来自 [PR #28](https://github.com/philfanzhou/ForgeSteward/pull/28)。

### prepare-work

- 数量规则：10 项仍为默认上限，目标改为在上限内输出尽可能多的 ready 项；用户数量要求优先。主线项达到 ready 或真实阻塞后，按排序继续准备冻结清单中的其余候选，直到达到上限或用户要求数量，或剩余候选均已判定不能入选并记录原因。
- 不能在只得到一两项 ready 时结束；缺少审计、验收、邻近问题归属或模板栏目等可在授权范围内补齐的候选须先补齐再判定。
- 保留“不凑数”：不降低门禁，不为增加数量拆分本应单一的 Issue 或新建任务，不纳入冻结后新出现的 Issue。入选数少于上限时在工作过程中说明其余候选的未入选原因，最终输出仍只含一行列表。
- 「持续推进主线阻塞」补充：先推进主线不等于只输出主线项。

## 迁移说明

- 无不兼容变化，不改安装 ID、调用方式或最终输出格式。
- 同一次调用会准备更多候选，耗时和对 Issue 的写入可能相应增加；需要更小批次时在调用时指定数量。

## 安装、升级与回退

以下命令仅在本版本发布确认后使用，适用于尚未配置同名市场的新环境。已有安装先按 [版本切换与清理指南](../versioned-installation.md) 记录所选子集、作用域和来源，卸载旧副本并替换市场 ref，再安装原子集；不要重复添加同名市场或直接修改缓存。指南中 `v0.2.1` / `find-work` 是历史示例，本版本必须同时换成 `v0.2.9` 和上表实际插件名。

Codex 新环境示例（其他插件按上表逐项安装）：

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.9
codex plugin add prepare-work@forge-steward
codex plugin list
```

Claude Code 新环境示例：

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.9
/plugin install prepare-work@forge-steward
```

OpenCode 使用独立快照，替换以下占位绝对路径；安装命令从要维护的目标仓库执行：

```bash
git clone --branch v0.2.9 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.9
git -C /absolute/path/ForgeSteward-v0.2.9 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.9/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.9/scripts/opencode.py status --all --project .
```

先核对 checkout SHA 与 Release 一致再安装；已有安装使用同快照安装器的 `update --all --project .`（或按记录指定子集和 `--user`），不是重复 `install`。本地定制触发保护时先备份、核对再决定，不强制覆盖。

ZCode 按 [固定版本与回退](../zcode.md#固定版本与回退) 将已核对的 `v0.2.9` 独立 checkout 根目录加入本地市场，选择插件子集并核对实际安装版本。切换前保存原来源、卸载旧插件并移除旧市场；不直接套用 Codex 的 `--ref` 或 Claude 的 `@tag` 输入。

从 `v0.2.8` 或 `v0.2.7` 升级只需切换版本，无额外迁移；从 `v0.2.6` 或更早版本升级，先阅读 [v0.2.7 迁移说明](v0.2.7.md#迁移说明)，其中 check-workflow 的删除行为是不兼容变化；从 `v0.2.1` 或更早版本升级，先移除退役 `find-work`，改装 `prepare-work`。所有已选插件均核对为 `0.2.9`。回退按相同步骤选择仍保留的 `v0.2.8`；回退不撤销已产生的项目改动、合并或托管平台操作。
