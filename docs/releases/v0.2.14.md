## 变更

- `work-cycle` 在第一个 Issue 准备周期前处理启动时已有的开放 Change Request。即使随后 `prepare-work` 返回 `[]`，存量 PR 仍完成审查、必要修复、符合门禁的合并与清理；启动审查不计入工作周期。
- `check-workflow` 每次调用只读查询仓库合并后自动删除源分支的设置，报告启用、停用或无法确认及证据。它不修改设置，也不因设置停用创建空 PR。
- `review-and-merge` 合并后回读远端源分支；平台尚未删除时，只有本仓源分支的 head 未变化、未受保护且未被其他开放 Change Request 使用，才自动删除并再次核对。本地分支继续按合并状态、head、工作区和共用情况安全清理。设置停用或未知不阻止逐项安全核对；无法确认或删除失败时保留并报告。

## 迁移说明

从 `v0.2.13` 升级后，明确调用 `work-cycle` 可能在准备任何新 Issue 前合并启动时已有的 PR。明确调用 `review-and-merge` 或经 `work-cycle` 派发审查后，已合并且符合安全条件的本仓远端源分支会自动删除，不再因仓库未启用自动删除设置而只提示用户处理。需要保留特定分支时，在调用中明确指定；调用仍受原验收、必要检查、审批、分支保护和平台权限约束。仓库设置不会被修改。

六个插件仍独立安装，但完整工作周期要求同版本的五个阶段插件和可创建、等待子 Agent 的运行环境。升级已固定到 `v0.2.13` 的市场或安装副本时，切换到本版本 Tag，并按[固定版本安装、升级与回退](../versioned-installation.md)保留原安装子集和作用域；仅更新 Agent 应用或刷新市场索引不等于更新技能。
