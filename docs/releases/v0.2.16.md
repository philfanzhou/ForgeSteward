## Changes and migration

- Low-quota or near-limit warnings do not mean a required capability is missing and are not stopping conditions. Dispatch required stages without reducing the requested cycle count or inventing preparation results.
- After stage handoff and remote-state verification, release completed threads from this orchestration using interfaces actually provided by the runtime. If no close interface exists, record the limitation and continue. Do not invent tools or assume interruption always releases a thread.
- After an actual creation or wait call fails, check task state first to avoid duplicate writes caused by an uncertain creation outcome. Ordinary wait timeouts continue using the original Agent.
- Each failure allows at most three rounds of state checks. Only the first two may recover and retry the operation after checking; the third is a final state check only. Recreate only when non-creation is confirmed, and keep the original task after a wait failure. Save the handoff and stop only when a required capability is confirmed missing or bounded recovery cannot continue. Report the actual error and recovery evidence.
- Independent subagents for each stage, fresh Agents for re-review, complete Skill loading, serial writes within a repository, and merge gates remain required.

Existing users should update their original plugin subset using [fixed-version installation, upgrades, and rollback](../versioned-installation.md). Full orchestration still requires all six plugins at the same version. No new invocation parameters, quota changes, or global configuration are needed, and user installations are not automatically changed.

## Validation and limitations

Locally, 148 unit tests ran: 145 passed and 3 were skipped because the real DeepSeek Provider was unspecified or the two Windows junction tests did not apply. OpenCode `1.18.32` and ZCode CLI `0.16.9` validated Skill discovery, complete bodies, and resources in isolated directories. Strict validation passed for all six Claude Code `2.1.283` plugins. Skill budgets and references, marketplace synchronization, Skill quick_validate, 50 relative documentation-link targets, and `git diff --check` all passed.

The PR's three-OS installer checks and pinned OpenCode `1.18.30` discovery check, plus all four checks on the merge commit, must pass. Actual SHA, check links, and results are recorded in the Release body.

Added [orchestration scenarios](../work-cycle-scenarios.md) covering low-quota warnings, stage cleanup, first-failure recovery, missing close interfaces, uncertain creation, normal waiting, wait errors, and exhausted recovery. An independent subagent performed read-only reasoning over six simulated snapshots, identifying and resolving ambiguity in counting state checks and operation retries. Existing byte-for-byte installer resource tests cover independent packaging of the new recovery rules. Rule walkthroughs and limited model scenario assessments do not constitute end-to-end certification of real quota failures, thread release, or full cross-Agent work cycles. This does not claim to fix the runtime's internal thread count or guarantee close interfaces on every platform.
