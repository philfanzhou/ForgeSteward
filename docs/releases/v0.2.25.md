This file is release input for `v0.2.25`. Publication is complete only when both the matching remote annotated Tag and a non-draft GitHub Release exist.

## Changes

- **Claude instruction consolidation** ([PR #127](https://github.com/philfanzhou/ForgeSteward/pull/127), [Issue #125](https://github.com/philfanzhou/ForgeSteward/issues/125)): after removing duplicate workflow policy, check-workflow can move retained tracked root `CLAUDE.md` and `.claude/CLAUDE.md` instructions into an existing root `AGENTS.md`, then remove a source only after verifying the destination. Preserve retained bytes, relative import targets and live references; omit only the exact duplicates and root imports permitted by the migration rules. Retain and report unsafe or ambiguous cases. Check-only remains read-only, and completed reruns make no changes.
- **English collaboration defaults** ([PR #128](https://github.com/philfanzhou/ForgeSteward/pull/128), [Issue #126](https://github.com/philfanzhou/ForgeSteward/issues/126)): after consolidation, check-workflow inspects existing collaboration-language rules and can add a fixed English default or replace a separable conflicting root rule. The default covers Issue and Change Request titles and bodies, Comments, Discussions and Review Feedback replies, with explicit maintainer-language and quoted-text exceptions. Preserve unrelated language conventions; report inseparable or external conflicts rather than overriding them.
- **Windows event recording and process cleanup** ([PR #131](https://github.com/philfanzhou/ForgeSteward/pull/131), [Issue #130](https://github.com/philfanzhou/ForgeSteward/issues/130)): treat Windows access-denied errors while acquiring a pending-deletion event guard as bounded contention within the existing ten-second deadline. Keep lock ownership, timeout and unrelated-error behavior. Concurrent-writer tests retain diagnostics and reap every child on failure, timeout or interruption. A native Windows pending-deletion regression failed before the repair and passed afterward; the original incident's discarded stderr remains unavailable, so its exact historical cause is not claimed.
- **Isolated test fixtures** ([PR #133](https://github.com/philfanzhou/ForgeSteward/pull/133), [Issue #129](https://github.com/philfanzhou/ForgeSteward/issues/129); [PR #134](https://github.com/philfanzhou/ForgeSteward/pull/134), [Issue #132](https://github.com/philfanzhou/ForgeSteward/issues/132)): prevent detached Git maintenance from outliving an installer fixture, and suppress interpreter bytecode in fake-command descendants on Apple Python. Preserve complete home-directory snapshots and prove that genuine configuration/cache additions, edits and removals are still detected.

## Upgrade and rollback

Use the version-pinned [installation and upgrade commands](../../README.md#supported-agents-and-installation) for `v0.2.25`. Upgrade all six plugins together when using work-cycle, then start a new Agent session. Publication does not change user installations automatically.

The check-workflow write boundary changes from deletion-only cleanup: an authorized run can now append retained instruction sections, remove eligible Claude entries, and add or replace the narrowly defined collaboration-language rule in an existing safe root instruction entry. Review the resulting cleanup Change Request before merging. Migration alone preserves instruction bytes; the subsequent language step may replace a separable conflicting collaboration rule. It does not translate existing Issues or Change Requests, alter unrelated documentation/code-comment/commit conventions, create missing instruction entries, or change global settings. See the bundled [migration rules](../../plugins/check-workflow/skills/forge-steward-check-workflow/references/agent-entrypoints.md), [language decision table](../../plugins/check-workflow/skills/forge-steward-check-workflow/references/collaboration-language.md), and [limited scenarios](../check-workflow-scenarios.md).

Direct Claude loading after source removal requires Claude Code `2.1.277` or later, enabled built-in `AGENTS.md` support and a compatible instructions mode/session. Ancestor/local Claude entries, relative imports and external-import approvals can still affect loading. Older or restricted sessions can restore root `CLAUDE.md` containing `@AGENTS.md`; check-workflow does not create that rollback file automatically. Never discard retained project instructions to perform a rollback.

Skill names, saved-record fields, event structure and CLI commands are unchanged. Rolling back the installed Skills does not undo project-file changes already merged. Preserve original records when using an older reader, as described in the [fixed-version rollback guide](../versioned-installation.md#switching-or-rolling-back).
