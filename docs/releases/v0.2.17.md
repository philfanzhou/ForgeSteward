## 变更与迁移

- 冻结队列后、轻量分诊前查询授权内目标仓库可用的开放自动化安全告警；类别示例和业务规则保持平台无关，具体查询能力由执行环境的平台适配提供。
- 如实区分查无告警、权限不足、平台不支持、失败和部分结果，记录时间、主线及覆盖。查询缺失不阻塞其他候选，不改变权限、扫描配置或告警状态。
- 告警先核实实际影响，再按现有门禁归并与登记；交接只保存脱敏定位和必要结论。已有冻结项可补证据，冻结后新登记项计为周期新增，留到后续重新冻结，不新增严重告警自动入队的例外。
- 完整告警规则放入包内[必读引用](../../plugins/prepare-work/skills/forge-steward-prepare-work/references/security-alerts.md)，由队列规则指定加载阶段；保留原入口、授权和 P01–P31/E01–E10 契约。

名称、调用输入、输出、安装 schema 和公共配置均未改变，无数据迁移。用户按[固定版本安装、升级与回退](../versioned-installation.md)显式更新原安装子集；完整编排仍需六项插件同版本。不需要新密钥、启用扫描或修改全局配置。本次不发布 Tag/Release，也不自动升级用户安装；回退技能不自动撤销既有告警或 Issue 状态。

## check-workflow 只读发布对账

- 每次检查同时按目标仓库成文发布契约比对发布标签、公告、必需包/feed、预发布标记、实际 latest 和适用的最近发布运行；缺少契约、授权或完整覆盖时逐维度写“无法确认”，明确不要求的渠道/运行写“不适用”。
- 对账发现只进最终汇报，不登记或修复、不进入目标仓库清理 Change Request 正文；与删除交付独立，零项目修改时仍明确声明。原“目标与授权”整节逐字保留，删除脚本和 work-cycle gate/168 小时及版本缓存机制零变化。
- 原完整汇报规则移到随包必读 `reporting.md`，新增独立 `release-audit.md`；入口、三份 manifest、Codex interface、Agent 默认 prompt 和 README 同步职责。安装/调用身份、输入、统一版本和项目文件只删除契约不变；不新增服务、密钥、状态库或数据迁移。用户显式更新所选源码快照；回退不撤销已交付清理或远端发布资产。
- 实施前远端 `v0.2.17` Tag 和 Release 均不存在，保持未发布目标 `0.2.17`，未发布 Tag/Release、未升级用户安装或改写历史版本表。

[场景与真实验收](../check-workflow-scenarios.md#0217-发布对账)记录 R01–R24 的有限人工演算，覆盖三方缺失、版本/标记/latest、草稿/运行、权限/能力/网络/部分结果、删除独立性、安全、取消和并发；不以正文关键字测试或模拟生产解析器冒充 Agent 行为验证。
