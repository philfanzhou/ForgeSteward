## Changes and migration

- After freezing the queue and before lightweight classification, query available open automated security alerts in authorized target repositories. Category examples and business rules remain platform-neutral; concrete query capabilities come from the execution environment's platform adapter.
- Accurately distinguish no alerts, insufficient permissions, unsupported platforms, failure, and partial results; record time, main-branch state, and coverage. Missing query access does not block other candidates or change permissions, scan configuration, or alert state.
- Verify alerts' actual impact before consolidating and recording them under existing gates. Handoffs retain only redacted locations and necessary conclusions. Existing frozen items may receive more evidence; newly recorded items after the freeze count as cycle additions and wait for a later freeze. There is no new exception automatically admitting severe alerts.
- Full alert rules live in the bundled [required reference](../../plugins/prepare-work/skills/forge-steward-prepare-work/references/security-alerts.md), whose loading stage is specified by queue rules. Original entry points, authorization, and P01–P31/E01–E10 contracts are preserved.

Names, invocation inputs, outputs, installation schema, and public configuration are unchanged; no data migration is required. Users explicitly update the original plugin subset using [fixed-version installation, upgrades, and rollback](../versioned-installation.md). Full orchestration still requires all six plugins at the same version. No new keys, enabled scans, or global configuration changes are needed. This work does not publish a Tag/Release or automatically upgrade user installations; rolling back Skills does not automatically undo existing alert or Issue states.
