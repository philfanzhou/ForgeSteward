# v0.2.21

This file is release input for `v0.2.21`. Publication is complete only when both the matching remote annotated Tag and a non-draft GitHub Release exist.

This release refined behavior using records of 0.2.20 runs across multiple repositories: simplify merging, prevent flaky tests from blocking unrelated PRs, and retain timed run records. It also resolved conflicts between language defaults and repository conventions and made reports more conversational. Review standards, merge conditions, and the three-repair limit per PR remained unchanged.

## Changes

- **Merge lane** ([PR #92](https://github.com/philfanzhou/ForgeSteward/pull/92), [Issue #87](https://github.com/philfanzhou/ForgeSteward/issues/87)): when branches must be current with main, one subagent holds the merge lock and processes approved, merely stale PRs in order: synchronize only the next, wait for checks, confirm differences come only from main, and merge. Conflicts go to repair. Do not synchronize every pending PR after each merge. If the repository already enables a platform merge queue, use it; do not enable queues or auto-merge on the repository's behalf. Rules are in review-and-merge `references/merge-lane.md`.
- **Retry unrelated CI failures once** ([PR #91](https://github.com/philfanzhou/ForgeSteward/pull/91), [Issue #86](https://github.com/philfanzhou/ForgeSteward/issues/86)): rerun once only if the failed test neither covers the change nor depends on changed code. Continue on a pass and register the flaky test as an Issue. Related or uncertain failures are not dismissed through reruns.
- **Run records and timing** ([PR #90](https://github.com/philfanzhou/ForgeSteward/pull/90), [Issue #85](https://github.com/philfanzhou/ForgeSteward/issues/85)): new work-cycle `scripts/run_record.py` creates `.git/forge-steward/runs/<run-id>/` per run, records stage start/end and CI/lock waits, and adds timing summaries to the final report. Evidence no longer goes in `/tmp`; retain only the latest 20 runs.
- **One leftover-branch cleanup per run** ([PR #89](https://github.com/philfanzhou/ForgeSteward/pull/89), [Issue #84](https://github.com/philfanzhou/ForgeSteward/issues/84)): orchestrated reviewers clean only their PR's own branches, without scanning the repository under the merge lock. One shared leftover cleanup happens at run completion. Standalone review-and-merge is unchanged.
- **Repository language takes precedence** ([PR #88](https://github.com/philfanzhou/ForgeSteward/pull/88), [Issue #83](https://github.com/philfanzhou/ForgeSteward/issues/83)): this release defaulted Issue/PR bodies to everyday Chinese, honoring other repository language requirements. Explicitly fill merge-commit title/body using repository commit conventions rather than copying the PR body.
- **Leftover branches and worktrees** ([PR #82](https://github.com/philfanzhou/ForgeSteward/pull/82), [Issue #81](https://github.com/philfanzhou/ForgeSteward/issues/81)): after its list, review-and-merge cleans branches left by merged/closed PRs, branches fully incorporated into main, and stale worktree records. Uncertain cases are listed only.
- **Plain progress updates** ([PR #80](https://github.com/philfanzhou/ForgeSteward/pull/80), [Issue #78](https://github.com/philfanzhou/ForgeSteward/issues/78)) and **removal of technical wording such as the Chinese term for triage** ([PR #79](https://github.com/philfanzhou/ForgeSteward/pull/79), [Issue #77](https://github.com/philfanzhou/ForgeSteward/issues/77)): progress, questions, and subagent returns also used everyday Chinese. Skill files removed the prohibited wording, with regression tests enforcing that restriction.

## Upgrade steps

Skill names, invocation, installation, and configuration did not change; no data migration was needed. Update installed plugins using [fixed-version installation, upgrades, and rollback](../versioned-installation.md). All six must use the same version for work-cycle.

Behavioral changes:

- With an up-to-date-branch requirement, the lane merges main into a PR branch without conflicts and pushes, using merge rather than force push. It uses an already enabled repository merge queue.
- Unrelated required CI failures are automatically retried once, with both run links retained on the PR.
- work-cycle stores run records under the target repository's `.git/forge-steward/runs/`; other record files left by older versions are not deleted automatically.
- Repository language requirements for Issues, PRs, and commit messages take precedence.
