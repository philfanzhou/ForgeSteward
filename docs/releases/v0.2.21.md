# v0.2.21

本文件是 `v0.2.21` 的发布输入。远端同名附注 Tag 和非 draft GitHub Release 都存在，才算发布完成。

这一版根据 0.2.20 在多个仓库的实测记录继续优化：合并阶段少走弯路、不稳定的测试不再拖住无关 PR、每次运行留下带耗时的记录；同时修正语言规则与仓库约定的冲突，并把汇报用语进一步改成日常说法。审查标准、合并条件和“每个 PR 最多改 3 次”都没变。

## 改了什么

- **合并车道**（[PR #92](https://github.com/philfanzhou/ForgeSteward/pull/92)，[Issue #87](https://github.com/philfanzhou/ForgeSteward/issues/87)）：仓库要求分支和主线保持最新时，已审查通过、只是落后的 PR 由一个子 Agent 拿着合并锁按顺序处理：只同步下一个、等检查、核对差异只来自主线、合并；有冲突交修复。不再每合并一个就同步全部待合并 PR。仓库已启用平台合并队列时直接加入队列；不替仓库开启合并队列或自动合并。规则在 review-and-merge 的 `references/merge-lane.md`。
- **与改动无关的 CI 失败只重跑一次**（[PR #91](https://github.com/philfanzhou/ForgeSteward/pull/91)，[Issue #86](https://github.com/philfanzhou/ForgeSteward/issues/86)）：失败的测试既不覆盖本次改动、也不依赖被改的代码时，重跑一次；通过就继续，并把时过时不过的测试登记成 Issue；有关或无法判断的失败不靠重跑放过。
- **运行记录与耗时**（[PR #90](https://github.com/philfanzhou/ForgeSteward/pull/90)，[Issue #85](https://github.com/philfanzhou/ForgeSteward/issues/85)）：work-cycle 新增 `scripts/run_record.py`，每次运行一个目录 `.git/forge-steward/runs/<运行编号>/`，记录各阶段开始结束和等 CI、等锁时间，最终报告附耗时汇总；证据不再放 `/tmp`；只保留最近 20 次。
- **遗留分支清理每次运行只做一次**（[PR #89](https://github.com/philfanzhou/ForgeSteward/pull/89)，[Issue #84](https://github.com/philfanzhou/ForgeSteward/issues/84)）：编排派发的审查只清理本 PR 自己的分支，不在合并锁内扫描全仓；整次运行收尾时统一清理一次。单独调用 review-and-merge 行为不变。
- **语言以仓库规定为准**（[PR #88](https://github.com/philfanzhou/ForgeSteward/pull/88)，[Issue #83](https://github.com/philfanzhou/ForgeSteward/issues/83)）：Issue、PR 正文默认日常中文，仓库另有规定时从其规定；合并提交标题和说明按仓库提交约定显式填写，不沿用 PR 正文。
- **遗留分支与 worktree 清理**（[PR #82](https://github.com/philfanzhou/ForgeSteward/pull/82)，[Issue #81](https://github.com/philfanzhou/ForgeSteward/issues/81)）：review-and-merge 处理完清单后清理已合并或已关闭 PR 留下的分支、已并入主线的分支和失效的 worktree 记录，拿不准的只列出。
- **进度说明也说人话**（[PR #80](https://github.com/philfanzhou/ForgeSteward/pull/80)，[Issue #78](https://github.com/philfanzhou/ForgeSteward/issues/78)）与**移除“分诊”等用语**（[PR #79](https://github.com/philfanzhou/ForgeSteward/pull/79)，[Issue #77](https://github.com/philfanzhou/ForgeSteward/issues/77)）：进度说明、提问和子 Agent 交回的结果同样用日常中文；技能文件不再出现禁用用语，并有测试守住。

## 升级需要做什么

技能名、调用方式、安装方式和配置都没变，没有数据迁移。按[固定版本安装、升级与回退](../versioned-installation.md)更新已安装的插件即可；用 work-cycle 时六个插件要升到同一版本。

行为上的变化：
- 仓库要求分支最新时，合并车道会把主线无冲突地合入 PR 分支并推送（用 merge，不强推）；仓库已启用合并队列时会使用它。
- 与改动无关的必要 CI 失败会被自动重跑一次，PR 中留有两次运行的链接。
- work-cycle 在目标仓库 `.git/forge-steward/runs/` 下保存运行记录；旧版本留下的其他记录文件不会被自动删除。
- 仓库对 Issue、PR 或提交信息有语言规定时，按仓库规定书写。

## 验证情况

- 本地测试 167 项：161 项通过，6 项因环境不适用而跳过；其中运行记录脚本测试 5 项（含 8 个进程同时写入）。
- 技能长度检查（含 Windows 换行余量）、版本一致检查（`sync_marketplace.py --check`）、`git diff --check` 通过。
- 各 PR 的三个系统安装器检查和 discovery 检查全部通过；本次 5 个 PR 均经 review-and-merge 技能逐项审查后合并。

没验证的：合并车道、合并队列和自动重跑只做了场景推演，没有在真实仓库里端到端运行；不能保证模型每次都照做。
