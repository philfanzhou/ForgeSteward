## 相对 v0.2.6 的变化

来自 [PR #22](https://github.com/philfanzhou/ForgeSteward/pull/22)、[PR #24](https://github.com/philfanzhou/ForgeSteward/pull/24)、[PR #23](https://github.com/philfanzhou/ForgeSteward/pull/23)。

### 工作流政策只以技能为准

- 四个工作技能不再采用仓库另行规定的同类工作流规则，包括 ready 门禁、任务粒度、Review 预算与轮次。语言、标题与提交格式、模板栏目、合并方式、必要检查与审批、分支保护、构建与验证命令等项目约定仍按仓库执行。

### prepare-work

- 新增 feature 级判定：同时涉及三个或以上公共协议面、三个或以上有状态产物，或耦合事务与并发、数据迁移、敏感数据流、能力启用中的多个领域时，按 feature 级处理；不能收敛为单一切片时拆为 tracker 与有依赖关系的 task，tracker 不入选。包含第二个独立契约、数据迁移或接口组时拆为独立 Issue。
- 复杂协议或状态任务须提供唯一语义模型，并逐场景演算端到端结果；形式检查不作为语义闭合证据。
- ready 门禁吸收原本写在项目规则和模板中的 Issue 约束：写明实现所属仓库和依赖；验收覆盖适用的失败、取消、安全、认证与密钥、数据迁移和并发结果及兼容与回滚结果；安全或健壮性任务写明保证、非保证、调用方责任和适用输入；审计范围包括公开文档、配置、数据迁移历史和部署路径；前置已关闭且平台依赖关联和标签与实际一致；邻近既有缺陷各自有 Issue 并链接；模板栏目留空视为未完成；ready 标记只在门禁满足时添加，不满足时移除。
- 不再以目标仓库排期规则优先于技能。

### execute-work

- 实施中发现范围达到 feature 级且无法收敛时停止该项并拆分跟踪；核对原 Issue 的语义模型，文档型目标设计记录实际演算的端到端场景。
- 每个 Change Request 只关闭一个原 Issue，正文记录实际命令、结果和跳过原因。

### review-and-merge 与 fix-feedback

- 统一轮次定义：出现要求修改的 Review Feedback 后作者推送新提交回应，计为一轮往返。依据平台时间线和交接记录计数，不一致时取较大值，不因换会话归零。
- 往返达到 3 轮或以上的 Change Request 不纳入冻结清单，等待人工处理：review 不审查、不合并、不评论；fix 不修改、不推送、不回复线程。只在输出中记录链接、轮次和计数依据。用户本轮明确点名的项除外。
- 已完成 2 轮往返的项，第三次审查或修复前先逐 commit 审计范围和语义闭合；不能追溯到原验收的改动列为阻塞或移出并另行登记。
- review-and-merge 将关联 tracker 或实际达到 feature 级的单一 task 列为范围内阻塞；两个技能不再采用仓库 Review 预算，可选建议不阻塞合并。

### check-workflow

- 从“同步标准区块”改为只删除、不写入：删除 `0.2.5`、`0.2.6` 写入的 `forge-steward:workflow` 与 `forge-steward:claude-rules` 区块（`scripts/remove_workflow_blocks.py --check|--write`），以及 Agent 指令、`CONTRIBUTING.md`、协作文档和 Issue/Change Request 模板中与技能重复的工作流政策，不区分项目自写还是旧版增补。判定依据见包内 `references/skill-owned-rules.md`。
- 删除前逐条核对维护技能中的等价条款；找不到等价语义的条文仍删除，但在 Change Request 中单列为“技能缺口”并引用原文。
- 移除 `assets/` 模板、`references/legacy-additions.md`、`references/agent-entrypoints.md` 和 `scripts/sync_workflow_block.py`；交付分支改为 `forge-steward/remove-skill-duplicates`。
- 决策、迁移说明和 J01–J19 场景见 [0.2.7 删除与技能重复的项目规则](../check-workflow-scenarios.md#027-删除与技能重复的项目规则)；四个工作技能的场景见 [技能工作流政策场景](../skill-owned-policy-scenarios.md)。

### 仓库维护规则

- 本仓库 `AGENTS.md` 新增：Agent 修改时仅当 `VERSION` 等于已发布版本才自动升版，否则保持未发布的目标版本。该规则只约束 ForgeSteward 仓库自身，不随插件分发。

## 迁移说明

- **check-workflow（不兼容的默认外部写入行为变化）**：升级后首次运行，会在一个 PR/MR 中删除旧版区块，以及 Agent 指令、贡献文档和模板中与技能重复的工作流规则，**包括项目自行编写的规则**。维护者可在审查中撤回任一删除。删除后这些约束只在调用技能时生效；不经过技能的会话或贡献者不再从项目文档读到它们。
- 项目需要与技能不同的工作流政策时，不能再通过项目规则覆盖技能，需修改技能本身。
- 四个工作技能不再遵守仓库自定的 ready 门禁、Review 预算和任务粒度规则。
- review-and-merge 与 fix-feedback 不再处理往返达到 3 轮的 Change Request；需要继续推进时由人工处理，或在调用时明确点名该项。
- `0.2.5`、`0.2.6` 创建的 `forge-steward/workflow-block` 开放 Change Request 由本版本取代；技能只报告，不自动关闭。0.2.5 的 G01–G14 与 0.2.6 的 H01–H10 场景不再适用。

## 安装、升级与回退

以下命令仅在本版本发布确认后使用，适用于尚未配置同名市场的新环境。已有安装先按 [版本切换与清理指南](../versioned-installation.md) 记录所选子集、作用域和来源，卸载旧副本并替换市场 ref，再安装原子集；不要重复添加同名市场或直接修改缓存。指南中 `v0.2.1` / `find-work` 是历史示例，本版本必须同时换成 `v0.2.7` 和上表实际插件名。

Codex 新环境示例（其他插件按上表逐项安装）：

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.7
codex plugin add check-workflow@forge-steward
codex plugin list
```

Claude Code 新环境示例：

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.7
/plugin install check-workflow@forge-steward
```

OpenCode 使用独立快照，替换以下占位绝对路径；安装命令从要维护的目标仓库执行：

```bash
git clone --branch v0.2.7 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.7
git -C /absolute/path/ForgeSteward-v0.2.7 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.7/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.7/scripts/opencode.py status --all --project .
```

先核对 checkout SHA 与 Release 一致再安装；已有安装使用同快照安装器的 `update --all --project .`（或按记录指定子集和 `--user`），不是重复 `install`。本地定制触发保护时先备份、核对再决定，不强制覆盖。

ZCode 按 [固定版本与回退](../zcode.md#固定版本与回退) 将已核对的 `v0.2.7` 独立 checkout 根目录加入本地市场，选择插件子集并核对实际安装版本。切换前保存原来源、卸载旧插件并移除旧市场；不直接套用 Codex 的 `--ref` 或 Claude 的 `@tag` 输入。

从 `v0.2.6`、`v0.2.5`、`v0.2.4` 或 `v0.2.3` 升级不改安装 ID 或调用方式；从 `v0.2.1` 或更早版本升级，先移除退役 `find-work`，改装 `prepare-work`，按需加装 `execute-work`，没有旧名 alias。所有已选插件均核对为 `0.2.7`。回退按相同步骤选择仍保留的 `v0.2.6`；回退不恢复 check-workflow 已删除的项目规则，也不撤销已产生的项目改动、合并或托管平台操作。

## 验证与非保证

发布前执行全量单元测试、统一版本/市场/资源和格式校验、相对链接检查；`tests/test_check_workflow_blocks.py` 在临时目录验证区块删除脚本。PR 与最终 main 的三个 OS 安装器检查及固定 OpenCode 发现检查必须通过，实际结果记录在 PR / Release。

工作流政策条文的删除由 Agent 按参考文档判定，不是脚本确定性结果；J09–J19、K01–K11、E11–E13、R01–R06、X01–X03 为人工条文走查，不等于独立 Agent 模型行为评测。PR #22 在一个真实使用方仓库只读运行了区块检查脚本，并按新规则人工整理了该仓库的清理 Change Request（尚未合并）；PR #24 对照该清理结果补齐了 prepare-work 缺失的 Issue 约束。ZCode 仍为开发预览，不代表 GUI 市场生命周期或模型行为已验证。

本次只发布 Git 快照和 GitHub 自动源码归档，不提供独立构建包；不修改本机真实安装或用户配置。
