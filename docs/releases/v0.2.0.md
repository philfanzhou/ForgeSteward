## Contents

- Four independent Skills: workflow adoption, selection of ready work, review and merge, and feedback repair. Authorization boundaries and rules for converging mainline work are preserved.
- Skill invocation names consistently use the `forge-steward-` prefix; plugin installation IDs are unchanged.
- OpenCode supports individual or full installation at project or user scope, explicit updates, uninstallation, receipts and conflict protection, and rollback after ordinary failures.
- Uninstallation reports candidate leftovers with missing receipts, manual copies, or old names. It does not automatically delete content of uncertain ownership or describe a limited scan as a whole-machine cleanup.
- Added installation/uninstallation, fixed-version and rollback instructions for three Agents, plus release procedures.

## Migration and use

See [fixed-version installation](../versioned-installation.md) and the [README](../../README.md). `@forge-steward` identifies the marketplace, not a package version. Users select a snapshot through the marketplace ref or source checkout.

- Migration from early `0.1.x` plugins: old invocation names have no aliases, so update saved prompts. Move manual copies together with their resources and check old directories separately, preserving user changes first.
- Users with the same `0.2.0` plugins and identical content do not need to force a reinstall. This first release pins the existing plugins and repository-level installer without changing Skill bodies again for publication.
- Installed OpenCode copies do not change automatically with a Git checkout; an explicit `update` is required. Run the repository-level installer directly from the selected source.
- An uninstall exit code of `0` only means there are no candidate leftovers for the selected target/names; `1` means an operation or scan failed, and `2` means leftovers remain. Argument usage errors also use `2`, so inspect the output.

## Validation and limitations

- The installer uses the Python 3.9+ standard library. The existing 43-test suite runs in macOS/Linux/Windows CI. Linux uses pinned OpenCode `1.18.30` to check real discovery and uninstallation, including the negative case where Skills remain discoverable despite missing receipts. Platform-inapplicable cases are explicitly skipped.
- Plugin content reuses earlier isolated-installation evidence from Codex CLI `0.154.0` and Claude Code `2.1.269`. Commands using this first release's pinned ref were checked against current help and official documentation; this does not mean end-to-end installation was repeated on every client.
- No native Windows OpenCode runtime validation was performed, and models are not guaranteed to follow the entire workflow every time. Automatic recovery from power loss, forced termination, or malicious concurrent writes is not guaranteed.
- Distribution consists only of Git snapshots; arbitrary combinations of historical package versions, as with NuGet, are not supported. User caches, other scopes, and manual copies must be checked separately.
