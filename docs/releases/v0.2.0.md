## 内容

- 四个独立技能：工作流接入、可开工任务筛选、审查合并、反馈修复。保留授权边界与主线收敛规则。
- 技能调用名统一使用 `forge-steward-` 前缀，插件安装 ID 不变。
- OpenCode 支持单个/全部、项目/用户级安装、显式更新、卸载、收据与冲突保护、普通失败回滚。
- 卸载后报告缺收据、手工或旧名候选残留；不自动删除归属不明内容，有限扫描不冒充整机清理。
- 补齐三 Agent 安装/卸载、固定版本与回退说明、发布规范。

## 迁移与使用

参见 [固定版本安装](../versioned-installation.md) 和 [README](../../README.md)。`@forge-steward` 指市场而非包版本；使用者通过市场 ref 或源码 checkout 选择快照。

- 从早期 `0.1.x` 插件迁移：旧调用名没有别名，更新保存的 prompt；手工副本需连同资源迁移并单独检查旧目录，先保留用户修改。
- 已安装相同 `0.2.0` 插件且内容相同的用户无需强制重装。首版将已有插件与仓库级安装器固定下来，没有为发布再次修改技能正文。
- OpenCode 已安装副本不随 Git checkout 自动变化：需要显式 `update`；仓库级安装器直接从所选源码运行。
- 卸载返回 `0` 只表示选定目标/名称无候选残留，`1` 表示操作或扫描失败，`2` 表示仍有残留（参数用法错误也用 `2`，应看输出）。

## 验证和边界

- 安装器使用 Python 3.9+ 标准库；现有套件 43 项，在 macOS/Linux/Windows CI 运行。Linux 的固定 OpenCode `1.18.30` 检查真实发现及卸载，包括缺收据仍能发现的负向场景；平台不适用项明确跳过。
- 插件内容复用早先 Codex CLI `0.154.0`、Claude Code `2.1.269` 的隔离安装证据；首版固定 ref 的命令按当前帮助和官方文档核对，不将此说成所有客户端都重新完成端到端安装。
- 无原生 Windows OpenCode 运行时验证；不保证模型每次遵循全部工作流。没有断电、强制终止或恶意并发写入的自动恢复保证。
- 只提供 Git 快照分发，不提供 NuGet 式任意历史包版本混搭。用户缓存、其他作用域及手工副本须分别核对。
