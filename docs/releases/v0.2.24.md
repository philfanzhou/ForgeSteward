## Changes

- **English content and defaults** ([PR #119](https://github.com/philfanzhou/ForgeSteward/pull/119), [Issue #118](https://github.com/philfanzhou/ForgeSteward/issues/118)): translate the 105 identified files across project rules, six Skills and their references, design and installation documents, historical release notes, script messages, comments, tests, and examples. New reports, status values, prompts, and collaboration instructions default to everyday English, while honoring an explicit user or target-repository language requirement.
- **Saved-record compatibility**: the single report specification defines exact aliases for the seven legacy result values and seven Agent states. Readers normalize these known fields in memory before validation, counts, and upgrade filtering. Equivalent old, new, and mixed records produce the same results without rewriting input files or translating user-provided free text. Invalid handoff data still fails validation; invalid Agent-check data still omits the optional upgrade section.
- **Content and link regression checks**: check all tracked text, including hidden configuration, for untranslated content and check relative Markdown links and heading fragments. Preserve narrowly identified technical Unicode inputs and legacy aliases as data. Keep the original UTF-8 byte, line, and UTF-16 description budgets; split queue and report-field guidance into required references included with their plugins.
- **Preserved behavior**: retain authorization, main-branch protection, repair limits, concurrent scheduling, resource locks, failure recovery, and explicit installation consent. Correct the reviewed scenario wording so dispatched subagents do not pause their work to wait for user answers. Historical notes in this snapshot are translated without changing historical behavior, version mappings, published Tags, or remote Releases.

## Upgrade and rollback

Follow the version-pinned [installation and upgrade commands](../../README.md#supported-agents-and-installation) for `v0.2.24`. Upgrade all six plugins together when using work-cycle, then start a new Agent session to load the updated Skills. This release does not upgrade user installations automatically.

Skill names, schema, field names, CLI commands, record paths, and event structure are unchanged. No on-disk migration is required for known legacy status values. New records and output use English; consumers that match localized status strings or rendered report text must update their expectations. User-provided free text and external command errors are not automatically translated.

Keep original records when rolling back to `v0.2.23` or an earlier release. Older readers may reject the new English status values; use saved old records or continue reading new records with the `v0.2.24` reader. Do not reverse-translate or overwrite user data. See the [saved-record compatibility details](../work-cycle-scenarios.md#english-migration-and-record-compatibility-118) and [fixed-version rollback guide](../versioned-installation.md#switching-or-rolling-back).
