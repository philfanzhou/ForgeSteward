## 相对 v0.2.5 的变化

均来自 [PR #20](https://github.com/philfanzhou/ForgeSteward/pull/20)，只涉及 check-workflow：

- **删除旧版增补**：`0.2.4` 及更早版本写入的增补规则没有标记，而区块外的项目规则优先于标准区块。check-workflow 现在按新增的 `references/legacy-additions.md` 取证，删除同时具备内容特征（旧约束维度且以补充形式出现）和提交历史证据的旧增补，与区块同步放在同一 Change Request 中，并逐项列出来源和判定依据。项目自行编写、加入后被实质修改、仍被引用、维护者明确保留或证据不足的内容不删除，列为待决定。区块已一致但仍有确认删除项时也会创建变更。
- **变更汇总**：运行修改了项目文件时（含仅本地修改或交付中途受阻），汇报按实际 diff 列出文件、操作、变更内容和增删行数，并说明修改状态和待决定候选；未修改时明确说明。其他技能不输出此汇总。
- 决策、迁移说明和 H01–H10、I01–I04 场景见 [0.2.6 删除旧版增补](../check-workflow-scenarios.md#026-删除旧版增补)。

## 迁移说明

- **check-workflow（默认外部写入行为变化）**：升级后首次运行，可能在同步区块的同一 PR/MR 中删除旧版技能写入的规则段落、为其新建的文档和读取指示。维护者可在审查中撤回任一删除；采纳并实质修改过的内容列为待决定，不自动删除。
- `0.2.4` 及更早版本“以前生成的内容一旦成为项目现有规则，也不得自动覆盖”的约定，不再适用于能确认的旧增补。
- 已用 0.2.5 追加标准区块、旧增补仍在的仓库，再次运行会产生一次删除变更。

## 安装、升级与回退

以下命令仅在本版本发布确认后使用，适用于尚未配置同名市场的新环境。已有安装先按 [版本切换与清理指南](../versioned-installation.md) 记录所选子集、作用域和来源，卸载旧副本并替换市场 ref，再安装原子集；不要重复添加同名市场或直接修改缓存。指南中 `v0.2.1` / `find-work` 是历史示例，本版本必须同时换成 `v0.2.6` 和上表实际插件名。

Codex 新环境示例（其他插件按上表逐项安装）：

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.6
codex plugin add check-workflow@forge-steward
codex plugin list
```

Claude Code 新环境示例：

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.6
/plugin install check-workflow@forge-steward
```

OpenCode 使用独立快照，替换以下占位绝对路径；安装命令从要维护的目标仓库执行：

```bash
git clone --branch v0.2.6 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.6
git -C /absolute/path/ForgeSteward-v0.2.6 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.6/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.6/scripts/opencode.py status --all --project .
```

先核对 checkout SHA 与 Release 一致再安装；已有安装使用同快照安装器的 `update --all --project .`（或按记录指定子集和 `--user`），不是重复 `install`。本地定制触发保护时先备份、核对再决定，不强制覆盖。

ZCode 按 [固定版本与回退](../zcode.md#固定版本与回退) 将已核对的 `v0.2.6` 独立 checkout 根目录加入本地市场，选择插件子集并核对实际安装版本。切换前保存原来源、卸载旧插件并移除旧市场；不直接套用 Codex 的 `--ref` 或 Claude 的 `@tag` 输入。

从 `v0.2.5`、`v0.2.4` 或 `v0.2.3` 升级不改安装 ID 或调用方式；从 `v0.2.1` 或更早版本升级，先移除退役 `find-work`，改装 `prepare-work`，按需加装 `execute-work`，没有旧名 alias。所有已选插件均核对为 `0.2.6`。回退按相同步骤选择仍保留的 `v0.2.5`；升级技能不自动迁移使用方仓库规则，回退也不恢复已删除的旧增补，不撤销已产生的项目改动、合并或托管平台操作。
