## Changes since v0.2.5

All changes come from [PR #20](https://github.com/philfanzhou/ForgeSteward/pull/20) and affect only check-workflow:

- **Remove old additions**: rules added by `0.2.4` and earlier have no markers, while project rules outside the standard block take precedence over it. check-workflow now gathers evidence using the new `references/legacy-additions.md` and removes old additions supported by both content characteristics (an old constraint category presented as an addition) and commit-history evidence. Removal and block synchronization share one Change Request, listing the source and decision evidence for each item. Content written by the project, substantially modified after addition, still referenced, explicitly retained by maintainers, or insufficiently supported by evidence is preserved for a decision. A change is also created when the block already matches but confirmed removals remain.
- **Change summary**: when a run modifies project files, including local-only changes or delivery interrupted by a blocker, the report lists files, operations, changed content, and added/deleted line counts from the actual diff, plus modification status and candidates awaiting a decision. It explicitly states when no changes were made. Other Skills do not produce this summary.
- See [0.2.6 removal of old additions](../check-workflow-scenarios.md#026-removal-of-old-additions) for decisions, migration notes, and H01–H10 and I01–I04 scenarios.

## Migration

- **check-workflow (change to default external writes)**: the first run after upgrading may delete rule paragraphs, documents created for them, and reading instructions written by older Skills in the same PR/MR as block synchronization. Maintainers can withdraw any deletion during review. Adopted content that was substantially modified is left for a decision and is not deleted automatically.
- The `0.2.4`-and-earlier rule against automatically overwriting generated content once it has become an existing project rule no longer applies to confirmed old additions.
- Repositories that added the standard block with 0.2.5 while retaining old additions will receive one removal change on the next run.

## Installation, upgrade, and rollback

Use these commands only after confirming this version has been released, in a new environment without a marketplace of the same name. For an existing installation, follow the [version switching and cleanup guide](../versioned-installation.md) to record the selected subset, scope, and source; uninstall old copies, replace the marketplace ref, and reinstall the original subset. Do not add the same marketplace twice or edit caches directly. The guide's `v0.2.1` / `find-work` examples are historical; for this version, replace both with `v0.2.6` and the actual plugin names in the table above.

Example for a new Codex environment (install other plugins individually using the table above):

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.6
codex plugin add check-workflow@forge-steward
codex plugin list
```

Example for a new Claude Code environment:

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.6
/plugin install check-workflow@forge-steward
```

For OpenCode, use a separate snapshot and replace the absolute placeholder paths below. Run installation commands from the target repository you want to maintain:

```bash
git clone --branch v0.2.6 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.6
git -C /absolute/path/ForgeSteward-v0.2.6 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.6/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.6/scripts/opencode.py status --all --project .
```

Before installing, confirm that the checkout SHA matches the Release. For an existing installation, use `update --all --project .` from the same snapshot's installer, or specify the recorded subset and `--user`, instead of repeating `install`. If local customizations trigger protection, back them up and inspect them before deciding what to do; do not force an overwrite.

For ZCode, follow [fixed versions and rollback](../zcode.md#fixed-versions-and-rollback) to add the root of the verified, separate `v0.2.6` checkout as a local marketplace, select the plugin subset, and confirm the installed versions. Before switching, save the original source, uninstall old plugins, and remove the old marketplace. Do not directly reuse Codex's `--ref` or Claude's `@tag` syntax.

Upgrading from `v0.2.5`, `v0.2.4`, or `v0.2.3` does not change installation IDs or invocation methods. From `v0.2.1` or earlier, first remove retired `find-work`, install `prepare-work` instead, and add `execute-work` as needed; there is no old-name alias. Confirm every selected plugin is `0.2.6`. Roll back with the same procedure by selecting the retained `v0.2.5`. Upgrading Skills does not automatically migrate consumer-repository rules; rollback neither restores deleted old additions nor undoes project changes, merges, or hosting-platform operations already performed.

## Validation and exclusions

Before release, run the full unit suite, unified-version, marketplace, resource, and format validation, and relative-link checks. Packaging tests assert that the new reference file ships with the package. The installer checks on all three operating systems and the pinned OpenCode discovery check must pass for both the PR and final main commit. Record actual results in the PR / Release.

An Agent identifies old additions from evidence gathered under the reference document; this is not a deterministic script decision. H01–H10 and I01–I04 are manual rule walkthroughs, not independent Agent model-behavior evaluations. PR #20 performed only a read-only trial in one real consumer repository, confirming that commit-history evidence could be located without modifying that repository. ZCode remains a development preview; GUI marketplace lifecycle and model behavior are not validated by these checks.

This release distributes only a Git snapshot and GitHub's automatic source archives, with no separate build packages. It does not change real local installations or user configuration.
