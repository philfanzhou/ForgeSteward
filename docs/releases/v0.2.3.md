## 变化与迁移

- `find-work` 退役为 `prepare-work`，不提供旧名 alias。持续完成可自主推进的调查、实验、方案和 Issue 整理；不实施生产代码。最终只给一行有序 Issue 标识，空结果为 `[]`，不再输出执行 prompt。
- 新增独立 `execute-work`，读取列表及原 Issue 证据，逐项实现、验收并提交独立 PR/MR，真实阻塞后继续其余独立项，不合并、不依赖 prepare 安装或旧会话。
- 承接 `0.2.2` 开发基线中 check-workflow 明确调用后默认补齐并提交 PR 的修复，以及全插件统一版本规则；check-workflow 的只读和本地限制仍有效。
- 新旧安装标识、单行交接、跨仓身份及安全迁移见 [迁移说明](../prepare-execute-migration.md)。旧固定版本安装示例保留，避免把未发布源码当作已发布快照。

## 验证与边界

发布前须完成全插件元数据、安装器回归、格式和市场校验、文档链接检查及适用的 Agent 安装发现；PR 记录实际命令、结果及 CI。准备/执行的有限规则走查见 [场景矩阵](../prepare-execute-scenarios.md)，不宣称进行模型行为或多轮真实业务交付测试。
