## Changes and migration

- `find-work` is retired in favor of `prepare-work`, without an alias for the old name. It continues investigations, experiments, planning, and Issue organization that can proceed autonomously, without implementing production code. Its final output is one ordered line of Issue identifiers, or `[]` when empty; it no longer produces an execution prompt.
- Added independent `execute-work`, which reads the list and original Issue evidence, implements and validates each item, and submits separate PRs/MRs. After a real blocker, it continues other independent items. It does not merge or depend on a prepare installation or old session.
- Includes the `0.2.2` development-baseline fix making explicit check-workflow invocation complete missing rules and submit a PR by default, plus the unified-version rule for all plugins. check-workflow's read-only and local-only restrictions remain effective.
- See the [migration notes](../prepare-execute-migration.md) for old/new installation identifiers, single-line handoffs, cross-repository identity, and safe migration. Old fixed-version installation examples remain to avoid presenting unreleased source as a published snapshot.
- Added ZCode development support using the Claude-compatible marketplace and plugin packages. Marketplace versions are derived from `VERSION` and checked in CI. Added entry-point adaptation, installation and upgrade, pinned-snapshot rollback, and uninstallation instructions without duplicating Skill bodies. See [ZCode support](../zcode.md) for validation scope.

## Validation and limitations

Before release, complete all-plugin metadata, installer regression, format, marketplace, documentation-link, and applicable Agent installation/discovery checks. Record actual commands, results, and CI in the PR. See the [scenario matrix](../prepare-execute-scenarios.md) for limited preparation/execution rule walkthroughs; no model-behavior or real multi-round delivery testing is claimed.

ZCode desktop 3.11.2 / bundled CLI 0.16.5 passed discovery and body-reading checks for five plugins in temporary directories. GUI marketplace installation, update, rollback, uninstallation, and model behavior were not validated; static/CLI checks do not constitute desktop end-to-end certification.

This PR neither publishes nor upgrades real user installations, and it does not authorize merging. Exact commit SHA, CI, and remote Release links must be added at release time.
