# ForgeSteward v0.2.1

兼容性修复发布，包含统一显示名及三种 Agent 的升级、卸载和旧版清理指引。项目仍处于 `0.x` 早期阶段。本文件是发布输入；以远端同名 Tag 与 [GitHub Release](https://github.com/philfanzhou/ForgeSteward/releases/tag/v0.2.1) 确认发布完成。完整提交 SHA、发布准备 PR 和最终主线 CI 链接记录在 Release 正文，不在本文件中循环嵌入自身 SHA。

每个插件的三份 manifest 均为 `0.2.1`；Codex 插件 `interface.displayName` 与技能 `agents/openai.yaml` 的 `display_name` 一致。四个插件均有包内显示元数据变化，因此分别提升 patch 版本；不是仅为 README 更新而统一升版。市场仍为 `forge-steward`，仓库 Tag 固定市场、安装器及文档，不提供任意插件历史版本混搭或独立 npm/PyPI/NuGet 包。

## 变更与迁移

- [PR #8](https://github.com/philfanzhou/ForgeSteward/pull/8)：统一四个插件及技能的 Codex 显示名，新增元数据回归测试，安装器测试不再硬编码上一包版本。
- [PR #9](https://github.com/philfanzhou/ForgeSteward/pull/9)：README 靠前提供 Codex、Claude Code、OpenCode 的升级步骤，以及作用域、缓存、残留和回退边界。
- 本次发布准备更新推荐 Tag、固定版本示例和本对应表；[v0.2.0 历史说明](v0.2.0.md) 保持不变。
- 从 `v0.2.0` 升级不改变安装 ID、技能调用名、默认 prompt 或技能正文，也不改变安装器实现。显示标签与调用标识是两回事，不需要重写已有调用名。

使用 [README 升级步骤](../../README.md#upgrade-and-keep-only-the-selected-version) 或[固定版本指南](../versioned-installation.md)选择 `v0.2.1`。Codex/Claude Code 先记录并移除原安装、替换市场 ref，再恢复原子集和作用域；OpenCode 选择源码 Tag 后显式 update。新会话核对版本与来源，用户改动先备份；固定 `v0.2.0` 后刷新市场不等于升级到本版本。回退使用同样流程选择 `v0.2.0`，不移动旧 Tag，不自动撤销技能已经产生的工作。

## 验证与非保证

- 46 项标准库测试覆盖安装、更新、过期文件替换、卸载、残留保护以及四组显示名/身份/版本一致性。macOS 本地运行 44 项通过，Windows junction 与未配置的真实 OpenCode 项明确跳过；最终三平台 CI 和固定 OpenCode `1.18.30` 的真实发现/卸载结果以 Release 记录为准。
- 四个 Claude 插件与市场严格格式校验通过；PR #8 已记录 Codex 插件和技能格式校验。安装/发现证据与显示元数据核对不等于所有桌面客户端渲染或模型行为的端到端验证。
- Claude Code `2.1.269` 使用独立临时配置与插件目录，通过本地市场安装四个 `0.2.1` 包；逐文件核对安装副本与发布源码相同，再卸载并确认安装列表为空。该验证不替代远端 Tag 获取或交互会话验证。
- OpenCode 安装器在临时项目先安装 `v0.2.0` 的四个技能，再用发布源码执行 `update --all`；四项均显示 `0.2.1 (matches checkout)`，随后全部卸载且选定目标无候选残留。未操作用户实际安装。
- 不修改使用者现有安装。Codex 桌面版的实际选择器显示、搜索和旧会话刷新仍需安装后在新会话确认；本发布不承诺所有客户端立即刷新。
- 不保证即时零磁盘残留：其他作用域、手工副本、退役名称及 Claude 后台清理期缓存需分别核验。不提供共享缓存的批量删除操作。
- 无原生 Windows OpenCode 运行时验证；保留既有断电、强制终止和恶意并发写入的非保证边界。
