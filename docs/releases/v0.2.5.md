## 相对 v0.2.4 的变化

- [PR #16](https://github.com/philfanzhou/ForgeSteward/pull/16)：check-workflow 不再逐项语义判断并撰写增补，改为按随包 `zh-CN` / `en` 模板同步根 `AGENTS.md` 中的 `forge-steward:workflow` 区块、`CLAUDE.md` 的 `@AGENTS.md` 导入及必要的读取指示区块。新增 `scripts/sync_workflow_block.py --check|--write`：缺失时追加、不同则整体替换、一致时零修改，区块外文字逐字节保留。决策与 G01–G14 场景见 [0.2.5 标准区块同步](../check-workflow-scenarios.md#025-标准区块同步)。
- [PR #17](https://github.com/philfanzhou/ForgeSteward/pull/17)：区块同步保留混用 LF/CRLF 文件中每一行原有的换行符；已存在的读取指示区块原位更新。
- [PR #18](https://github.com/philfanzhou/ForgeSteward/pull/18)：明确调用 review-and-merge（包括仅选择技能、不附加 prompt）即授权合并审查通过的 Change Request，满足合并条件后直接合并，不再逐项请求确认。标准模板“阶段与授权”同步说明明确调用阶段技能即授权其默认流程。

## 迁移说明

- **check-workflow（不兼容行为变化）**：以前版本增补的段落没有标记，不会被识别或删除；首次运行新版本会在旁边追加标准区块，维护者可在审查中删除重复的旧增补。区块内的手工修改会在下次运行时被覆盖，项目差异应写在区块外。
- **review-and-merge（默认外部写入行为变化）**：以前明确调用后仍会在合并前等待确认，现在满足合并条件即直接合并。只需审查时，须在请求中明确说明“仅审查，不合并”。合并条件、分支保护、必要审批和平台权限约束不变；自动加载或仅提及技能名称仍不构成合并授权。
- 已在使用方仓库合入旧版标准区块（0.2.5 开发期间）的，下次运行 check-workflow 会因模板“阶段与授权”一条的变化产生一次同步变更。

## 安装、升级与回退

以下命令仅在本版本发布确认后使用，适用于尚未配置同名市场的新环境。已有安装先按 [版本切换与清理指南](../versioned-installation.md) 记录所选子集、作用域和来源，卸载旧副本并替换市场 ref，再安装原子集；不要重复添加同名市场或直接修改缓存。指南中 `v0.2.1` / `find-work` 是历史示例，本版本必须同时换成 `v0.2.5` 和上表实际插件名。

Codex 新环境示例（其他插件按上表逐项安装）：

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.5
codex plugin add check-workflow@forge-steward
codex plugin add review-and-merge@forge-steward
codex plugin list
```

Claude Code 新环境示例：

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.5
/plugin install check-workflow@forge-steward
/plugin install review-and-merge@forge-steward
```

OpenCode 使用独立快照，替换以下占位绝对路径；安装命令从要维护的目标仓库执行：

```bash
git clone --branch v0.2.5 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.5
git -C /absolute/path/ForgeSteward-v0.2.5 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.5/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.5/scripts/opencode.py status --all --project .
```

先核对 checkout SHA 与 Release 一致再安装；已有安装使用同快照安装器的 `update --all --project .`（或按记录指定子集和 `--user`），不是重复 `install`。本地定制触发保护时先备份、核对再决定，不强制覆盖。

ZCode 按 [固定版本与回退](../zcode.md#固定版本与回退) 将已核对的 `v0.2.5` 独立 checkout 根目录加入本地市场，选择插件子集并核对实际安装版本。切换前保存原来源、卸载旧插件并移除旧市场；不直接套用 Codex 的 `--ref` 或 Claude 的 `@tag` 输入。

从 `v0.2.4` 或 `v0.2.3` 升级不改安装 ID 或调用方式；从 `v0.2.1` 或更早版本升级，先移除退役 `find-work`，改装 `prepare-work`，按需加装 `execute-work`，没有旧名 alias。所有已选插件均核对为 `0.2.5`。回退按相同步骤选择仍保留的 `v0.2.4`；升级技能不自动迁移使用方仓库规则，回退也不撤销已产生的项目改动、合并或托管平台操作。
