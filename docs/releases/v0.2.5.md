The actual full commit SHA, release PR, and final main-branch CI links are recorded in the Release body.

## Changes since v0.2.4

- [PR #16](https://github.com/philfanzhou/ForgeSteward/pull/16): check-workflow replaces item-by-item semantic assessment and authored additions with synchronization from bundled `zh-CN` / `en` templates: the `forge-steward:workflow` block in root `AGENTS.md`, the `@AGENTS.md` import in `CLAUDE.md`, and necessary reading-instruction blocks. Added `scripts/sync_workflow_block.py --check|--write`: append missing blocks, replace differing blocks in full, and make no changes when identical, preserving text outside blocks byte for byte. See [0.2.5 standard block synchronization](../check-workflow-scenarios.md#025-standard-block-synchronization) for decisions and G01–G14 scenarios.
- [PR #17](https://github.com/philfanzhou/ForgeSteward/pull/17): block synchronization preserves each line's original ending in files mixing LF/CRLF; existing reading-instruction blocks are updated in place.
- [PR #18](https://github.com/philfanzhou/ForgeSteward/pull/18): explicit review-and-merge invocation, including selecting the Skill without an added prompt, authorizes merging Change Requests that pass review. Merge directly once conditions are satisfied, without requesting confirmation for each item. The standard template's stage-and-authorization rule likewise states that explicit invocation of a stage Skill authorizes its default workflow.

## Migration

- **check-workflow (incompatible behavior change)**: paragraphs added by previous versions have no markers and are not identified or removed. The first run of the new version appends the standard block beside them; maintainers can remove duplicate old additions during review. Manual edits inside the block are overwritten on the next run; project-specific differences belong outside it.
- **review-and-merge (change to default external writes)**: previously, explicit invocation still waited for confirmation before merging; now it merges directly once conditions are met. For review alone, explicitly request “review only, do not merge.” Merge conditions, branch protection, required approvals, and platform permissions are unchanged. Automatic loading or merely mentioning the Skill still does not authorize merging.
- Repositories that merged an older standard block during 0.2.5 development will receive one synchronization change on their next check-workflow run because the template's stage-and-authorization rule changed.

## Installation, upgrade, and rollback

Use these commands only after confirming this version has been released, in a new environment without a marketplace of the same name. For an existing installation, follow the [version switching and cleanup guide](../versioned-installation.md) to record the selected subset, scope, and source; uninstall old copies, replace the marketplace ref, and reinstall the original subset. Do not add the same marketplace twice or edit caches directly. The guide's `v0.2.1` / `find-work` examples are historical; for this version, replace both with `v0.2.5` and the actual plugin names in the table above.

Example for a new Codex environment (install other plugins individually using the table above):

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.5
codex plugin add check-workflow@forge-steward
codex plugin add review-and-merge@forge-steward
codex plugin list
```

Example for a new Claude Code environment:

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.5
/plugin install check-workflow@forge-steward
/plugin install review-and-merge@forge-steward
```

For OpenCode, use a separate snapshot and replace the absolute placeholder paths below. Run installation commands from the target repository you want to maintain:

```bash
git clone --branch v0.2.5 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.5
git -C /absolute/path/ForgeSteward-v0.2.5 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.5/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.5/scripts/opencode.py status --all --project .
```

Before installing, confirm that the checkout SHA matches the Release. For an existing installation, use `update --all --project .` from the same snapshot's installer, or specify the recorded subset and `--user`, instead of repeating `install`. If local customizations trigger protection, back them up and inspect them before deciding what to do; do not force an overwrite.

For ZCode, follow [fixed versions and rollback](../zcode.md#fixed-versions-and-rollback) to add the root of the verified, separate `v0.2.5` checkout as a local marketplace, select the plugin subset, and confirm the installed versions. Before switching, save the original source, uninstall old plugins, and remove the old marketplace. Do not directly reuse Codex's `--ref` or Claude's `@tag` syntax.

Upgrading from `v0.2.4` or `v0.2.3` does not change installation IDs or invocation methods. From `v0.2.1` or earlier, first remove retired `find-work`, install `prepare-work` instead, and add `execute-work` as needed; there is no old-name alias. Confirm every selected plugin is `0.2.5`. Roll back with the same procedure by selecting the retained `v0.2.4`. Upgrading Skills does not automatically migrate consumer-repository rules; rollback does not undo project changes, merges, or hosting-platform operations already performed.

## Validation and exclusions

Before release, run the full unit suite, unified-version, marketplace, resource, and format validation, and relative-link checks. The installer checks on all three operating systems and the pinned OpenCode discovery check must pass for both the PR and final main commit. Record actual results in the PR / Release.

`tests/test_check_workflow_block.py` automatically covers script behavior for G01–G10. G11–G14 and review-and-merge's default merging behavior are manual rule walkthroughs, not independent Agent model-behavior evaluations. ZCode remains a development preview; GUI marketplace lifecycle and model behavior are not validated by these checks.

This release distributes only a Git snapshot and GitHub's automatic source archives, with no separate build packages. It does not change real local installations or user configuration.
