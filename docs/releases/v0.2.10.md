## 相对 v0.2.9 的变化

### prepare-work

来自 [PR #30](https://github.com/philfanzhou/ForgeSteward/pull/30)。

- 本轮按任务粒度规则从冻结候选拆分出的 task 继承冻结身份，逐项判定门禁；tracker 仍不入选，依赖链上仍依赖未合并前置的 task 不入选。
- 深入准备前先对完整冻结清单做只读轻量分诊：已有开放实现、属于 tracker、依赖未合并前置，或已记录真实外部阻塞且解除条件未变的候选直接判为不能入选；分诊不代替门禁，也不因预估投入大而排除候选。
- 非主线候选需要多轮长耗时调查时，保存证据和下一动作后可先推进排在其后的候选；批次未满时须回到该项，最终列表仍按排序输出。
- 主线等待长耗时结果（CI、环境构建、外部回复等）期间推进其余候选；等待不解除主线的持续推进义务，也不把主线判为外部阻塞。
- 输出前复核扩展到解除条件已在本轮满足的未入选冻结候选，入选数仍受上限约束。
- 删除“一两项”措辞；frontmatter `description` 与默认 prompt 体现在默认上限或用户数量内填满批次。
- 测试：OpenCode 真实发现测试改为将输出写入临时文件，避免 macOS 上管道输出在 65536 字节处截断。

### review-and-merge

来自 [PR #31](https://github.com/philfanzhou/ForgeSteward/pull/31)。

- 合并后删除已合并 Change Request 的本地源分支及专用 worktree，不再以“由本轮创建”为条件；有未提交改动或本地 head 与已合并 head 不一致时保留并报告。
- 新增远端源分支核对：读取仓库是否启用合并后自动删除源分支并回读远端分支状态。未启用、无法读取设置或分支仍存在时，不自行删除远端分支，也不修改仓库设置；合并完成后提示用户保留的分支和设置状态，由用户决定是否启用自动删除或手动删除。提示不暂停冻结清单，并在输出汇总。
- 用户本轮明确授权删除远端分支时，仅删除已合并、远端 head 与已合并 Change Request 一致且位于本仓库的源分支。

## 迁移说明

- 无不兼容变化，不改安装 ID、调用方式或最终输出格式。
- review-and-merge 现在会删除非本轮创建、但已合并且无独有工作的本地源分支；需要保留时在调用时说明。
- 仓库未启用合并后自动删除源分支时，review-and-merge 的输出会多出一条提示；如需自动清理，可在托管平台启用对应设置。

## 安装、升级与回退

以下命令仅在本版本发布确认后使用，适用于尚未配置同名市场的新环境。已有安装先按 [版本切换与清理指南](../versioned-installation.md) 记录所选子集、作用域和来源，卸载旧副本并替换市场 ref，再安装原子集；不要重复添加同名市场或直接修改缓存。指南中 `v0.2.1` / `find-work` 是历史示例，本版本必须同时换成 `v0.2.10` 和上表实际插件名。

Codex 新环境示例（其他插件按上表逐项安装）：

```bash
codex plugin marketplace add philfanzhou/ForgeSteward --ref v0.2.10
codex plugin add review-and-merge@forge-steward
codex plugin list
```

Claude Code 新环境示例：

```text
/plugin marketplace add philfanzhou/ForgeSteward@v0.2.10
/plugin install review-and-merge@forge-steward
```

OpenCode 使用独立快照，替换以下占位绝对路径；安装命令从要维护的目标仓库执行：

```bash
git clone --branch v0.2.10 https://github.com/philfanzhou/ForgeSteward.git /absolute/path/ForgeSteward-v0.2.10
git -C /absolute/path/ForgeSteward-v0.2.10 rev-parse HEAD
python3 /absolute/path/ForgeSteward-v0.2.10/scripts/opencode.py install --all --project .
python3 /absolute/path/ForgeSteward-v0.2.10/scripts/opencode.py status --all --project .
```

先核对 checkout SHA 与 Release 一致再安装；已有安装使用同快照安装器的 `update --all --project .`（或按记录指定子集和 `--user`），不是重复 `install`。本地定制触发保护时先备份、核对再决定，不强制覆盖。

ZCode 按 [固定版本与回退](../zcode.md#固定版本与回退) 将已核对的 `v0.2.10` 独立 checkout 根目录加入本地市场，选择插件子集并核对实际安装版本。切换前保存原来源、卸载旧插件并移除旧市场；不直接套用 Codex 的 `--ref` 或 Claude 的 `@tag` 输入。

从 `v0.2.9`、`v0.2.8` 或 `v0.2.7` 升级只需切换版本，无额外迁移；从 `v0.2.6` 或更早版本升级，先阅读 [v0.2.7 迁移说明](v0.2.7.md#迁移说明)，其中 check-workflow 的删除行为是不兼容变化；从 `v0.2.1` 或更早版本升级，先移除退役 `find-work`，改装 `prepare-work`。所有已选插件均核对为 `0.2.10`。回退按相同步骤选择仍保留的 `v0.2.9`；回退不撤销已产生的项目改动、合并或托管平台操作。
