# v0.2.23

本文件是 `v0.2.23` 的发布输入。远端同名附注 Tag 和非 draft GitHub Release 都存在，才算发布完成。

这一版简化 work-cycle 的安装情况汇报：只在有 Agent 可以安装或升级，或当前会话技能包较旧时显示第 7 节；同时把 Codex 的只读插件查询限定到 ForgeSteward 市场，减少无关远端目录查询带来的等待。六个插件统一升到 `0.2.23`。

## 改了什么

- **汇报只显示需要升级的安装情况**（[PR #115](https://github.com/philfanzhou/ForgeSteward/pull/115)，[Issue #113](https://github.com/philfanzhou/ForgeSteward/issues/113)）：work-cycle 第 7 节只列缺少、不完整或落后的 Agent；已是最新、无法判断和开发版不再逐项列出。当前会话的技能包版本从包内 `scripts/VERSION` 读取，较旧时单独提示。检查不可用、最新版未知或没有可展示内容时省略第 7 节；完整检查 JSON 仍保留，前 6 节照常生成。安装授权、检测 JSON 和安装动作不变。
- **Codex 检查限定当前市场**（[PR #116](https://github.com/philfanzhou/ForgeSteward/pull/116)，[Issue #114](https://github.com/philfanzhou/ForgeSteward/issues/114)）：只读查询使用 `codex plugin list --marketplace forge-steward --json`，跳过无关远端目录获取，仍从 `installed` 数组读取插件名和版本。macOS CLI `0.157.1` 的本机对照中，无过滤查询约 0.936 秒，限定查询约 0.059 / 0.045 秒，六个插件结果一致；这不是所有环境的耗时保证。单条 20 秒和整体 60 秒的等待边界不变；选项不支持、查询失败、超时或格式变化时记为无法判断，不重试、不退回无过滤查询、不读取内部缓存补结果。

## 升级需要做什么

技能名、调用方式及安装数据格式不变，无需数据迁移。按 [README](../../README.md#supported-agents-and-installation) 更新到 `v0.2.23`；运行 work-cycle 时六个插件须使用同一版本。

行为上的变化：最终汇报不再固定显示 7 节，无升级信息时只显示前 6 节。当前会话使用旧技能包时，更新安装后仍需新建会话，才能加载新版本。Codex 限定市场查询已核对 CLI `0.157.1`；旧 CLI 不支持时只影响该 Agent 的安装状态检查，不中断仓库工作。

## 验证情况

- 本次功能 PR #115、#116 的 Linux、macOS、Windows 安装器检查和固定 OpenCode discovery 检查均通过。
- 发布准备的本地全套测试 241 项：235 项通过，6 项因环境不适用而跳过；运行时设置 `PYTHONDONTWRITEBYTECODE=1`，避免 Apple Python 在测试的临时 HOME 中写入字节码缓存。

- 发布前等待发布 PR 与确切 main 合并提交的四项 CI 全部通过。实际提交 SHA 和 CI 链接记在 GitHub Release 中。
- 发布仅包含 Git 仓库快照和 GitHub 自动源码归档，不提供独立构建包。

验证边界：本机 Codex 查询对照为只读实验；CLI 旧版本兼容由失败路径测试覆盖，没有逐个运行历史版本。未调用模型验证技能行为，也不宣称任意模型、配置或客户端的端到端保证。真实 Agent 升级的结果以发布后本机复查为准。
