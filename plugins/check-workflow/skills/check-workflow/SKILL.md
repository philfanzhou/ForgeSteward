# Check Workflow

## 目标与授权

帮助代码库首次接入发现任务、审查交付和修复意见的工作流。检查现有规则是否能支持各阶段，并在用户要求接入、补齐或修改文档时直接完成缺失约束的增补；只要求检查或分析时仅输出报告及建议补丁。沿用当前任务中有效的授权，不因切换会话重复询问。

只修改目标仓库内相关工作流约束文档及必要的 Agent 文档入口。保留项目已有规则的文字、含义、适用范围、优先级和加载路径；不能借“接入工作流”替换、弱化或强化已有要求，也不能以新增段落间接覆盖旧规则。遵循目标仓库的文档语言，不把 ForgeSteward 自身的语言、技术栈或工程规则带入使用方。

不修改业务代码、依赖、测试实现、CI、分支保护、全局 Agent 配置或权限；不安装插件，不批量整理 Issue，不自动运行其他 Skill，不合并 Change Request。commit、push、创建 Change Request 按用户授权及目标仓库流程处理；未授权发布时仍完成允许的本地文档修改和可审阅差异。

## 读取与建立约束映射

1. 定位用户指定的目标仓库、主线和工作区，记录基线与已有改动。项目要求通过分支交付时先创建工作分支；不覆盖用户改动、不在主干直接 commit 或 push。目标跨仓时分别确认范围，不因接入一个仓库自动修改另一个。
2. 完整读取适用的项目/目录级 Agent 指令、贡献指南、工作流说明和 Issue/Change Request 模板，并沿其声明的引用定位真实规则源。读取已配置的 Agent 文档入口及加载配置，识别覆盖、回退、导入关系；无法读取的来源记为未知。只按需查看验证命令或目录边界的证据，不转为代码缺陷审计。
3. 按 [工作流最低约束](references/workflow-requirements.md) 逐项建立“要求 → 现有来源及适用范围 → 状态 → 缺少部分 → 拟增补位置”。按语义判断，接受等价措辞和现有文件布局，不以固定标题、文件名或模板格式作为通过条件。
4. 状态区分：**已满足**、**缺失且可增补**、**与既有规则冲突**、**不适用**、**来源/语义待确认**。已有更严格或不同但明确的政策原样保留；不能简单取“更严格者”，也不能宣布本 Skill 或新文档优先于项目规则。

## 只增补缺失项

- 对已满足项只引用原文位置，不重复抄写。对部分满足项仅补缺少的语义，不重写原段落、不统一格式、不顺手翻译或迁移旧文档。
- 对可增补项写出具体、有限且可验证的执行条件，并引用项目原有测试入口、术语、任务层级及交付流程。不虚构命令、审批人数、三轮预算、十项批次或“一 PR 一 task”等项目政策；已有这些要求则保留，用户本轮明确的批次要求也不能被默认值缩减。
- 对冲突或未知项，保留原规则，记录来源、触发场景、受影响阶段和需要的具体决定；不写入冲突条款，不扩大成全面规范整改。继续其他独立、无冲突的增补；存在未决必需项时只能报告部分接入，不能声称全部兼容。
- 优先在现有权威工作流文档中增加缺失段落。确实没有合适位置时才新增一份符合项目布局的工作流文档，并在适用入口增加明确的读取指示。已有“唯一规则源”约定必须保留，不新增第二个权威。
- 增补内容限定用于本工作流，声明其补充性质及原规则来源；不要求历史 Issue 批量套模板、不把接入检查变成每次任务执行的前置审计。具体任务仍须按项目规则验收，规则文档齐全不代表任务 ready。
- 再次运行先检查等价内容及入口。已补齐且来源未变时不产生新段落、时间戳、重复引用或无意义 commit。以前生成的内容一旦成为项目现有规则，也不得自动覆盖或升级；发生冲突时按同一流程报告。

## 多 Agent 入口

读取 [Agent 入口适配](references/agent-entrypoints.md)，只为用户指定或仓库已采用的 Agent 添加必要文档入口；未指定且无现有入口时采用其中的最小通用布局。技能本体保持标准 `SKILL.md` 与相对引用，不依赖特定工具名、shell、平台 API、上下文压缩命令或其他 Skill 已安装。

新增入口前必须验证它不会遮蔽已有回退文件、绕过目录规则或形成循环。复用项目原来的规则源，用薄入口引用，不能给每个 Agent 复制一套工作流正文。需要修改非文档配置、用户级配置或无法验证加载语义时，只报告该适配缺口和可执行下一步，不擅自修改，也不将其算作已兼容。

## 验证与结束条件

1. 对照执行前的文件内容核对 diff：原有文字、模板字段和用户改动均保留；新增内容确实只对应缺失项，没有冲突的隐式重定义。仅有新增行不足以证明语义不变，还须检查规则作用域和加载优先级。
2. 检查每项增补的来源、适用阶段和停止条件；检查相对路径存在、入口可达、无导入循环、无同义重复，包含实际使用的根目录和相关子目录。已有检查工具适用时运行；不为验证文档而触发生产流程或安装新工具。
3. 复核约束映射并做一次不写入的重跑判断：每个已完成项应为“已有覆盖”，拟新增差异应为空。缺少来源或保留冲突不靠标记“完成”消除。
4. 允许的文档增补完成并验证后结束；已全部满足时以零修改结束；有冲突或环境限制时交付已完成部分、具体缺口及下一步。不存在必须继续扩大调查才能满足的“完美规则”条件。

用目标项目约定的语言汇报：基线与操作模式、已满足/新增/保留冲突/未知/不适用的清单和来源、实际修改文件、原规则保留证据、各 Agent 的入口路径与验证层级、重跑判断、交付状态及下一步。区分“文档及路径已验证”“Agent 实际加载已验证”和“行为已验证”；没有运行目标 Agent 时不得宣称运行时兼容。未获发布授权时给出本地 diff；已授权开 Change Request 时提交并返回链接，禁止合并。
