# 工作流最低约束

用于逐项对照项目规则和生成必要增补，不是整份复制到目标仓库的统一模板。下列默认补充仅在项目没有等价规则且不存在冲突时使用；保留现有规则及用户明确要求，不把 ServiceMantle 或 ForgeSteward 的项目特例变成所有仓库的标准。

## 检查与补充范围

| 要求 | 足够支持工作流的约束 | 缺失时可补充的最小语义 |
| --- | --- | --- |
| 规则来源与阶段应用 | Agent 能定位当前项目规则及目录作用域；任务能引用适用约束 | 开始任务时读取适用规则，记录来源、适用阶段和所需证据；Skill 默认行为不得替代项目明确要求 |
| 任务范围与实施归属 | 有目标、范围、排除项和实际实现仓库；有可执行的范围变更处理 | 实施前固定本任务边界；超范围发现先分类，不能因邻近代码或 Review 意见自动吸收；跨仓回链原任务，不复制同范围任务 |
| 逐条验收 | 完成条件能映射到断言或其他可核对证据，适用测试维度明确 | 缺少验收依据时先补清楚再实施；实现与适用的成功、失败、取消、安全、并发验证一起交付，不适用须说明，不以 CI 全绿代替逐条验收 |
| 保证与非保证 | 安全/健壮性任务约定适用输入、保证边界、排除项及调用方责任 | 对适用任务明确有限、可验证的保证和非保证；不能为了可收敛而缩减既有保证；其他任务允许不适用 |
| 开工门槛 | 已核对必要代码/测试/契约、实际前置及开放实现，符合项目 ready 条件 | 没有现成审计时做任务所需的有限调查；有审计时先核对相关变化；标签、清晰描述或历史绿色结果不单独证明 ready；设计调查可以先于生产实现 |
| 主线与批次 | 主线、未完成项及批次范围可恢复；阻塞有下一步和出口 | 先推进已有主线的具体阻塞，不靠持续寻找小任务绕过；外部条件未变不重复调查；批次不自动扩容、单项受阻继续独立项，不依赖未合并代码。数量及并行方式沿用项目/用户要求 |
| Review 分类与结束 | 能区分当前验收/保证缺口、独立既有缺陷、可选建议及平台门禁 | 范围内必修项附依据；非保证建议默认不构成代码必修项，已有预算原样沿用；真实争议记录决策人和解除条件，不能为了满足意见扩大实现，不绕过平台审批 |
| 修复与复审 | 待修清单有完成条件，已解决和待复审状态可区分 | 只处理确认的必修项，完成必要验证后按授权推送原分支；记录依据后交回复审，不反复修改已解决项，不因推送完成宣称任务交付 |
| 新发现分诊 | 有去重和分类方式，不默认改变当前范围或排期 | 区分当前验收遗漏、独立缺陷、可选改进和已接受边界；按项目方式登记，已关闭任务遗漏回链为返工；严重风险写明触发、影响、处置及恢复条件，不强制每条建议新开 Issue |
| 持续交接与证据复用 | task/变更、提交、证据、意见和下一步可跨会话恢复 | 记录任务与实现仓库、base/head、规则/审计来源、验收证据、意见分类、轮次、已解决意见、已接受边界、阻塞及解除条件；沿用已授权位置，无可写位置时输出完整交接；未知不推定通过 |
| 交付与结项 | 已推送、已验收、已合并、已关闭可区分；层级项目有父项检查 | 实查合并与原任务剩余范围，符合规则才结项；有父子结构时检查直接父项、完成后再向上，不靠子项全关代替父级验收；没有父子结构不新建层级 |
| 清理周期 | 清理目标与新增/返工分开，不能通过反复重置基线显示进展 | 仅在积压清理周期记录期初任务及剩余范围，原交付、新增、返工、父级结项分别报告；拆分或迁移不算完成。不为单次普通维护强制创建 tracker |
| 授权与临时环境 | 分析、文档增补、代码修改、发布、合并边界可区分，清理不损失工作 | 按用户实际请求的工作流、明确限制及项目规则执行；仅清理本任务拥有且无未保存工作的环境，不从仅引用 Skill 名称或自动加载推定合并或外部发布授权 |

## 约束映射与有限输出

检查表使用“要求 / 现有文件与章节 / 适用范围 / 状态 / 最小增补或待决定事项”。引用既有等价规则即可，不重复维护它们的正文，也不要求目标项目采用本表中的标题。

若需新增独立文档，只包含尚未覆盖的条款、适用范围和现有规则源引用；若已有文档允许增补，直接追加相关段落。按项目语言落文，不附带需要每轮更新的生成时间或动态审计结果。

典型判断：

- 项目要求 Issue 显式写出验收：不能以“代码已有测试”为由宣布 ready，保留该要求。
- 项目已有五轮建议预算或合并必须两人批准：原样保留，不改成三轮或零审批。
- 项目要求所有可选建议修完才能合并：记录与工作流结束条件的冲突，不通过追加“可选建议不阻塞”暗中覆盖。
- 项目没有数据库、父任务或跨仓工作：对应维度可不适用，不新增数据库测试、父级层次或仓库迁移要求。
- 项目已有完整流程：只给出覆盖证据及零修改结论，不为了接入留下重复规范文件。
