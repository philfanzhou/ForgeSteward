# Freeze the complete queue

1. Resolve each original Issue to a unique identity; deduplicate in input order. Preserve the full requested count: do not reorder, reduce to one item, or add tasks. Record each status, the cleanup cycle's original tasks, unfinished scope, and exit conditions.
2. Read each original Issue, comments, acceptance criteria, exclusions, preparation evidence, and linked implementation. Identify the code-owning repository, mainline, and workspace state. Across repositories, preserve the tracking identity and backlinks; do not duplicate the same Issue scope.
3. Read implementation-repository conventions and refresh remote mainline and open Change Requests. A ready label or input source alone is insufficient. For linked or clearly overlapping open implementations, establish coverage; do not duplicate work or take over someone else's branch. Record existing coverage and remaining scope, then continue independent items. Repairing existing PRs requires separate authorization.
4. Check prerequisites and start evidence. For a complete existing audit, compare its commit, relevant mainline changes, implementation/test/contract coverage, and unresolved items. Reuse it if relevant content is unchanged; otherwise read affected members, tests, and call paths in full. Fill evidence gaps as needed without requiring prepare-work again or repeating a repository-wide audit for unrelated commits.
5. Investigate gaps in environment, acceptance, or design through authorized research, experiments, and Issue updates until implementable or genuinely blocked. If scope requires a new independent contract, or is feature-sized (at least three public protocol surfaces, at least three stateful outputs, or coupling multiple domains among transactions/concurrency, migration, sensitive data flows, and capability enablement) and cannot be narrowed to one independently verifiable slice, stop that implementation. Record the split plan (one tracker plus dependent tasks, or the separate independent slices) on the original Issue, remove a stale ready marker when authorized, and stop that item. Do not create Issues or add tasks to this queue; a later preparation round may create and prepare them under its rules. A tracker itself gets no implementation Change Request. Record concrete blockers, attempts, and release conditions on the original Issue, then continue independent items.
