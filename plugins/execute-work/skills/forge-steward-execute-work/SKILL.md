# Execute Work

## 输入与授权

接收用户给出的 Issue 编号、平台限定标识或完整 URL 列表，例如 `#123, #145, #167`。不要求安装或先运行 prepare-work，也不依赖它生成的 prompt 或先前会话；实施依据来自原 Issue、持久化证据和所属仓库规范。

用户明确调用本技能并提供清单时，默认要求读取、实现、验证、提交、推送并创建 Change Request，不在一个 PR 提交后结束。遵守用户更窄的只读、本地修改、禁止发布等边界；隐式匹配技能或只讨论名字不额外授予写入权限。本技能不合并，合并由单独授权的审查流程处理，不自动调用其他技能。

单独调用而没有清单时请求缺失的 Issue 列表，不自行发现任务；输入 `[]` 时说明没有待执行项，不写代码或创建空 PR。短编号依据明确的跟踪仓库解析，无法唯一定位时先请求澄清，不能猜测仓库或把多个同号任务合并。使用实际托管平台可用的连接器、CLI 或 API，不硬编码平台。

## 冻结完整执行队列

1. 将清单解析成原 Issue 的唯一身份，按原顺序去重，保留用户要求的完整数量，不重新排序、不缩成单项、不自动补新任务。记录每项状态及清理周期原 task、未完成范围和退出条件。
2. 逐项读取原 Issue、评论、验收、排除项、准备证据及关联实现，识别实际拥有代码的仓库、主线和工作区状态。跨仓保留原跟踪身份和回链，不复制同范围 Issue。
3. 读取实现仓库的规范，刷新远端主线和开放 Change Request。不能只信 ready 标签或输入来源；有关联或明显重合的开放实现时确认覆盖范围，不重复创建，也不擅自接管他人分支。记录已有实现及未完成范围，继续其余独立项；修复既有 PR 的工作按另行授权处理。
4. 检查前置和开工证据。已有完整审计先核对其 commit、相关主线差异、实现/测试/契约覆盖及未决项，无相关变化则复用；相关变化补读受影响完整成员、测试及调用路径。缺失证据时完成必要补查，不强制用户重跑 prepare-work，也不因无关主线提交反复全仓审计。
5. 若环境、验收或设计存在缺口，先执行授权范围内可完成的调查、实验或 Issue 补充，持续至可实施或确认真实阻塞。范围需新增独立契约时按仓库要求更新或拆分跟踪，不将新项自动加入冻结队列。无法推进的项记录具体原因、已尝试动作和解除条件，再继续独立后项。

## 逐项实现与提交

- 为每项独立基于所属仓库当时最新远端主线建立工作分支或隔离工作区，不叠加前一项未合并代码；保护用户改动和他人工作。必须依赖未合并实现的项记录等待条件，不能把批量执行解释成堆叠 PR 的授权。
- 先确认范围内的不变量，再修改最小必要实现及配套测试。Issue 的排除项有约束力；不能顺手重构、升级依赖或吸收第二个独立契约。调用链有多条路径时按同一保证验证适用输入集合，不只修报告中的单一路径。
- 逐条对应“验收条目 → 实际断言或可检查产物 → 执行结果”，执行与修改风险匹配的本地验证及仓库必需检查。适用的失败、取消、安全和并发行为随实现验证；未覆盖项保留未完成。旧绿色结果、总测试数或 CI 全绿都不能代替逐条验收。
- 邻近问题先检索开放和关闭记录去重。当前范围内的保证违反在本项闭环；独立既有缺陷及可选改进另行分诊并链接，在原 Issue/PR 写清本次不修。已关闭 task 的验收遗漏回链原实现与遗漏条目，计为返工，不包装成新需求。只有需立即处置的严重风险可以中断顺序，记录影响和恢复条件。
- 检查 diff、敏感信息、用户改动及提交范围后，提交并推送本项工作分支，创建独立 Change Request，回链原 Issue。标题、正文、模板和一个 PR 的关闭范围遵守所属仓库规则。正文说明最终实现、逐条验证、已知限制和刻意不修的归属，不能宣称已经合并交付。
- 发布前复核是否出现等价开放实现，避免重复。写入或推送返回不确定时先查询远端状态再重试；发布失败保留本地提交与恢复动作。检查已启动的必要 CI，处理确定且在范围内的失败；外部故障或等待保留未完成状态，不扩大成全仓修复或反复审查循环，也不阻断独立后项。若仓库允许先提交草稿等待环境验证，准确标为草稿/未验收，不假报通过。

## 连续执行与恢复

每项达到已提交、已有实现覆盖、已完成无须修改或真实阻塞的状态后，继续冻结清单的下一项，直到全部处理。用户明确停止或变更范围时更新队列；切换目录、压缩上下文、提交首个 PR 都不是结束整个批次的理由。轮询外部检查不应妨碍可独立进行的后项。

沿用已有授权 tracker 或任务记录，保存完整有序清单及每项状态、原 Issue/Change Request 链接、实现仓库、基线和 head、分支/工作区、验收证据、仍有效的审计、意见分类与 review 轮次、已解决意见和已接受边界、阻塞及下一步。没有外部可写位置时保留会话交接，不虚构已经持久化；跨上下文恢复时读取记录，不将未完成项遗漏或 review 轮次归零。

仅清理本任务拥有、干净且无独有未交付工作的临时环境。未合并 PR 的分支保留用于后续修复；有失败、未推送提交或必要实验产物时保存路径和恢复方式，不为“环境干净”删除工作。

## 最终报告

使用中文按原顺序汇总全部项：原 Issue、实际状态、实现及验证、Change Request 链接、遗留与解除条件。区分已提交、已验收、已合并交付，不因提交 PR 关闭原 task 或重置清理周期。期初任务完成/剩余、新增分诊、返工和父级结项分列，未知计数不猜测；无关联项写不适用。最后说明保留的分支/工作区及恢复动作。
