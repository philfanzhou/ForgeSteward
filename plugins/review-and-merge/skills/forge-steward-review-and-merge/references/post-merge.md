## 合并后结项

1. 重新读取远端合并状态和目标分支结果，再核对关联任务是否正确完成；仅在验收实际满足且仓库流程允许时关闭任务。跨仓任务不得假设自动关闭，须检查原仓实际状态；缺少权限时交接具体结项动作，无关联任务则明确报告。
2. 检查直接父任务的子项、父级验收及相关未解决缺口；父级完成后再逐层向上核对。仍有未完成范围时写明剩余项及归属，到此停止，不因子项全关就关闭父项，也不借结项开展全仓审计。
3. 更新本地主线：本地存在主线分支时，获取远端后在检出主线且没有未提交改动的工作区中执行 `git merge --ff-only <远端>/<主线>`（如 `origin/main`）快进到合并结果；该命令作用于当前检出分支，不在其他分支上执行。主线所在工作区有未提交改动或不能快进时保留原状并报告，不重置或强制覆盖。
4. 清理本地分支：合并完成后删除已合并 Change Request 在本地的源分支及专用于它的 worktree，不以是否由本轮创建为条件。删除前确认没有未提交改动，且本地分支 head 与已合并 Change Request 的 head 一致（即没有未推送的独有提交）；该分支不是默认或受保护分支，且没有其他开放 Change Request 使用它。不满足时保留并报告。当前检出该分支时先按第 3 步切换到主线。`git branch -d` 拒绝删除不能作为分支未合并的证据：squash 或 rebase 合并后原提交不在主线历史中，这种拒绝很常见。此时以平台合并状态和上述 head 核对为准，一致后强制删除。移除 worktree 后执行 `git worktree prune` 清理残留记录。
5. 清理远端源分支：读取仓库是否启用合并后自动删除源分支（例如 GitHub 的 Automatically delete head branches，GitLab 的默认删除源分支选项或该 Merge Request 的删除源分支选项），并回读远端分支实际状态；设置只作诊断，不修改。平台已删除时记录结果。仍存在时，仅对本仓库的已合并源分支，在删除前重新确认远端 head 与该 Change Request 合并时的 head 一致、分支不是默认或受保护分支、没有其他开放 Change Request 使用它，随后删除并再次回读。设置停用或无法读取不阻止这项安全核对与清理。fork、来源不明、head 已变化、分支被共用或保护状态无法确认时保留并报告原因；删除失败时记录错误和保留分支，继续处理冻结队列。用户明确要求保留的分支不删除。
6. 每项结束后按入口的[交接记录](../SKILL.md#交接记录)交接，包括未合并或受阻项；确认当前项状态后继续冻结清单，不为新增可选建议延长本轮。
